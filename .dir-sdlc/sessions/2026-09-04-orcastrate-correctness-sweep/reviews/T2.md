## Findings

**Blocking: none.**

**Advisory 1 — criterion 11's behaviour is met by the code but has no regression pin.**
`tests/unit/helm/watcher.test.ts:249` pins `HelmWatcher`'s treatment of
`sha256Of('')` vs `null`, but it never calls `save`. If a future edit
reintroduced a `content === '' ? null : sha256Of(content)` branch at
`helm-service.ts:231`, nothing under `tests/unit/helm` would go red. Not
blocking — criterion 11 asks for a behaviour, not for a test. No options — advisory.

**Advisory 2 — T2's stated reason for that gap is wrong, though its conclusion stands.**
T2 reported the empty serialization unreachable "without editing a file T2 does
not own", but `src/main/helm/document.ts` **is** inside `src/main/helm/**`, so
T2 does own it. The correct reason is scope: widening `serializeSettings`'
output floor is a behaviour change no criterion asks for. Recorded because the
justification, not the conclusion, was faulty. No options — advisory.

**Advisory 3 — `BackupSequence` is per-`Helm`-instance state.**
`helm-service.ts:79-83`, `private readonly backups`. Two `Helm` services
constructed in one process against the same settings file would each start at
ordinal 0 and could still collide inside one millisecond. Contract section 1
scopes out a second *process*; the in-process multi-instance case is not
contemplated by any criterion. Noted only so it is not mistaken for covered.
No options — advisory.

**Advisory 4 — the report's accounting of test-file edits was incomplete.**
`watcher.test.ts`'s import block was rewritten, adding `join`, `sha256Of`,
`HelmWatcher`, `draftFrom`, `testClock` and `tempRoot`. No assertion in a
pre-existing test moved, so criterion 15 is unaffected, but T2's report named
only `helpers.ts:28` and the `write-safety.test.ts` import. No options — advisory.
