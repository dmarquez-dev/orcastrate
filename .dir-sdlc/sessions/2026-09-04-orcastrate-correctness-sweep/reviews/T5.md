## The blocking finding and its resolution

**Finding (raised by the orchestrator, not by the round-1 reviewer):**
`src/renderer/src/beachcomber/BeachcomberRow.test.tsx(189,36): error TS2345:
Argument of type 'number | undefined' is not assignable to parameter of type
'number | bigint'` — the only non-`TS6307` error in the whole web typecheck.

Round 1 could not have caught it: T5's acceptance criteria carried no typecheck
gate, and vitest transpiles without typechecking, so 70 tests ran green over a
file that did not compile. Root cause found by the implementer:
`tsconfig.web.json:24` sets `noUncheckedIndexedAccess: true`, so destructuring
`positions(...)` typed both bindings `number | undefined`.

**Fix:** a `positionOf(root, node, label)` helper that throws a named error when
the position is `undefined` **or** `-1`, replacing the destructure. The
implementer rejected a `!` or `as number` cast on the grounds that both failure
modes would then flow into the comparison, and `-1` in particular compares
cleanly and could make the order assertion pass for the wrong reason. It
subsumes the old `expect(noticeAt).toBeGreaterThanOrEqual(0)` line, which is why
that assertion is gone rather than moved.

**Resolution verified by the reviewer:** `npx tsc -p tsconfig.web.json --noEmit`
→ **24 `error TS` total, 24 `TS6307`, 0 matching `beachcomber`** (counts via
`grep -c` on captured output). (reviewer-reproduced)

**Blocking: none.**

**Advisory 3 — two idioms for the same guard.** The `positions` helper still
returns raw `-1` sentinels, and the two V4 tests guard them with
`expect(ordered.filter((at) => at < 0)).toEqual([])` — a different idiom from
the `positionOf` throw now used in V1. Harmless and correctly guarded; a later
cleanup could route V4 through `positionOf` too.
`BeachcomberRow.test.tsx:165-170`, `211-215`. No options — advisory.

**Advisory 4 — carried up from the implementer, for the orchestrator.** The
frontend discipline says nothing about index access under
`noUncheckedIndexedAccess`, which is why the destructure looked idiomatic when
it was written. A line stating that destructuring or indexing a
`querySelectorAll`/`map` result needs an explicit guard would prevent the same
error recurring. The implementer did not edit the discipline — it is outside its
glob. No options — advisory.
