## The `WorkspaceProvider` seam

T5 does not exist yet, so `renderWithWorkspace` resolves a provider from a runtime registry (`registerWorkspaceProvider` / `resolveWorkspaceProvider`) and **throws** with a message naming the fix when none is registered. There is deliberately no default passthrough — a stand-in that merely rendered `children` would let a peer's test go green while the real state layer was never exercised. Verified as throwing.

## Advisory findings

1. **The `#?raw` CSS import is advisory, not blocking** — the reviewer formed this independently on the vacuous-pass question, not on style. If Vitest's `vitest:css-disable` ever matches the fragment form, `tokensCss` becomes `''`, `declaredNames` is empty, and `missing` becomes all 43 token names, so the assertion fails loudly; the single-`:root` test and the `global.css` positive assertions fail too. If the default were `undefined` instead, `stripComments` throws. **There is no path on which it passes vacuously**, which is the property that decides it. Rationale already documented in `css.d.ts`. `styles/tokens.test.ts:22-23`.
2. **`test-utils/index.ts` re-exports `./render`**, which imports `@testing-library/react` and registers a module-level `afterEach(cleanup)`. A peer's **node**-environment test that imports the barrel for `stubOrcastrateApi` alone pulls in DOM code. `stub-api.test.ts` sidesteps this by importing `./stub-api` directly; peers doing node-side stub work should do the same. `test-utils/index.ts:12`.
3. **`package-lock.json` gained `"peer": true` markers** on existing `react-dom` and `@types/react-dom` entries as npm resolution churn — harmless, but it makes the lock diff larger than the three additions.
4. **`styles/css.d.ts` declares `*.css` with a `string` default export.** A side-effect-only `import './global.css'` from `main.tsx` works either way, but a peer reading that declaration might assume the text is available at runtime in the app bundle, which it is not.
