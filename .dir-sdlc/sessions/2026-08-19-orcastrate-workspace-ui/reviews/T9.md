## Judged decisions — all three sound

- **Control on the tab, not the composer.** Correct. Criterion 1 scopes the affordance to a *listed* Pod, but the composer only ever exists for the *active* one — a composer-mounted control would leave every backgrounded unopened Pod without one. The bar is the only surface rendering every listed Pod.
- **One `pod-tab-open:<podId>` id for both modes.** No collision. `TEST_IDS` explicitly permits an unlisted internal id that does not collide, `testId` joins on `:`, and the string is distinct from `pod-tab:`, `pod-tab-permission:`, and `pod-tab-bypass:`. Collapsing both modes to one id is what makes criterion 3's "no control reachable" a single query.
- **The focus effect.** Correct as written. It fires only on the true→false transition and bails unless `activeElement` is `null` or `body`, so a user who deliberately moved focus keeps it. Mount is safe: the ref is seeded from the current value, so a Pod mounting already-open takes the early return.

## Advisory findings

1. `openError` is a single workspace-wide string, not per-Pod. An error from one Pod's open renders unattached to any tab and persists until the next attempt — it is not cleared when the user selects, closes, or deletes the failing Pod. Criterion 4 only requires verbatim rendering and continued interactivity, both of which hold. `pods/PodsChrome.tsx:33`
2. The beached predicate is computed twice independently — `PodTab.tsx:91` picks the *label*, `PodsChrome.tsx:56` picks the *verb*. They agree today and the tests assert label and verb together, but a future edit to one could show "Open" while calling `reconnectPod`. A shared helper would tie them.
3. The focus effect could in principle move focus to a *background* tab if a status push (rather than a click) flipped that Pod's control off while focus sat on `body`. Not reachable today, since the two actions have no caller but this control.
4. `handleOpen` falls through to `openPod` when the tab lookup misses. Harmless — the store answers an unknown id with an error the same path renders. `pods/PodsChrome.tsx:56`
