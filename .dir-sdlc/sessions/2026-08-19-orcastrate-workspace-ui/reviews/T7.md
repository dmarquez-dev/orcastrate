## The three unsettled decisions, judged

- **`readOnly` instead of `disabled` on the textarea — satisfies criterion 2, does not evade it.** The criterion requires *Send* be disabled and that disabled state produce `disabledReason`-derived text rather than swallowing input; both hold, with Send using real `disabled`. The reasoning is load-bearing rather than convenient: `disabled` removes the element from the tab order, and criterion 3's Esc-to-interrupt must work in exactly the `awaiting-permission` case. **Choosing `disabled` would have made criteria 2 and 3 mutually unsatisfiable.**
- **Empty draft not disabling Send — correct reading of the contract.** `renderer-state.ts:436-438` makes a whitespace-only send a *local* `INVALID_ARGUMENT` that never reaches IPC, whereas `renderer-view.ts:262-268` says of the deny reason specifically that Deny must not enable until the field is non-empty. The contract draws that distinction deliberately in two places; the implementer followed it rather than generalising one rule over the other.
- **Focusing on any externally-set text — correct.** Criterion 5 forbids recognising the prefill string, so "text I did not just produce" is the only prefix-blind signal available.

## Advisory findings

1. Stale cross-reference at `permissions/PermissionCards.module.css:8` — it names `PermissionCardList.test.tsx` as the stylesheet reader, but the reader is `PermissionCards.styles.test.ts`. That comment is the guard rail pointing future editors at the test that would catch a modal regression, so the wrong filename blunts it.
2. Prefix-collision risk with T8's queries: internal ids `permission-card-list`, `permission-card-input`, `permission-card-submitting`, `permission-card-error` share a prefix with the contract's `permission-card`. None collide exactly, but a T8 query written as `getAllByTestId(/^permission-card/)` without the colon picks up four non-cards. T7's own tests correctly anchor on `/^permission-card:/`.
3. `suppressedError` is never reset to `null` (`Composer.tsx:65`). Harmless today because comparison is by identity and the state layer builds a fresh `IpcError` per failure — but if it ever returns a memoized singleton per code, a second identical failure would be silently hidden.
4. An empty-draft Send reaches the state layer, so the user learns via a rendered error rather than a dimmed button. Contract-consistent, but the asymmetry with the deny-reason treatment is worth a look if the UX is revisited.
5. `orderCards` copies and sorts on every render. Irrelevant at the expected card count; noted only because the list re-renders on every keystroke in any reason field.
