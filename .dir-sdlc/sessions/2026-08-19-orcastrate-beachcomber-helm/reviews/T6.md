failed. The reviewer did not re-sabotage (it was instructed not to edit) and
instead verified the assertions **discriminate** — the property is observed in
both polarities inside the passing suite, which is what rules out vacuity:

- **Orphan guard (spot-checked hardest):** `BeachcomberRow.test.tsx:106-114`
  forces `makeUnverifiedRow({ orphan: true })` — the fixture's `...overrides`
  spread lands after `orphan: false`, so the entry genuinely claims orphanhood —
  and asserts the marker is null. The sibling at `:121-126` renders a
  session-record orphan and asserts the same query returns an element reading
  "Working directory no longer exists". Dropping the `pathSource` conjunct makes
  the first query return that element. **The test fails. Genuine.**

  one through the same accessor — not a constant.
- **`actionError`:** one test requires the surface with `phase: 'ready'` and
  `actionError` set; another requires its absence with nothing to say.
- **"Delete now":** the counter is proven live elsewhere (driven to 1 in the
  dialog suite), so the panel test's exact `0` is an observation rather than a
  stuck zero, and any enabled button wired to `trashPreviewed` falls inside the
  sweep.

## Advisory findings

1. **The unverified notice says "below" but the path renders above it.**
   `BeachcomberRow.tsx:77` renders `displayPath` above `UNVERIFIED_PATH_NOTICE`,
   whose frozen text reads "…so the path below is a guess." Verbatim rendering is
   what criterion 5 requires and is met; the spatial word is simply now wrong.
   **Cheapest fix is DOM order, not copy — the copy is frozen.** Carry to Gate 3.
2. **Refusals name a reason but not the entry.** `BeachcomberRefusals.tsx:36-38`
   renders `refusal.reason` only, so "This entry is not part of the current scan.
   Rescan first." does not say which entry. Criterion 7 asks for the reason and
   gets it; adding `displayPath` would make the list actionable.
3. **One user-visible sentence bypasses `copy.ts`.**
   `BeachcomberGroupHeader.tsx:63` composes `Select all in ${group.heading}` in
   JSX, against that file's own stated rule.
4. **A stricter reading of criterion 13 exists.** `BeachcomberPreviewDialog.tsx`
   and `BeachcomberResult.tsx` each compose child components *and* author their
   own headings. The reviewer read the criterion as binding on arrangers, found
   the two actual arrangers clean, and judged it met — flagging the alternative
   reading rather than acting on it.
5. **The three judgment-call assumptions hold up.** Binary units match the recycle
   bin the user checks next; the ISO day is the only cross-machine-assertable
   form; and the real `disabled` attribute is what "responds to neither click nor
   keyboard" literally demands, since `aria-disabled` alone leaves a checkbox
   operable. The row carries both, so nothing is lost.
6. **Bare percentage lengths, `z-index: 1` and `opacity: 0.6`** match established
   repo convention in three sub-session 2 stylesheets. Not a deviation.
