it temporarily set `panelBar={null}`, ran `failure-paths.e2e.test.tsx`, and
restored the file — reporting 8 failures before its change and 6 after.

The reviewer re-ran that suite read-only and found exactly the reported 6, then
corroborated the delta by a different route: **`beachcomberScan` and `helmScopes`
now pass**, and those channels fire only on panel-hook mount, so the sweep
demonstrably opens both panels. Without the strip they had no invocation path and
would have failed identically to the other four. **Claim holds; none of the 6 is a
T9 defect.**

The remaining 6, attributed:

- **2 are pure arithmetic** over `INVOKE_KEYS` — the surfaced list is 12 where a
  literal expects 6. Unrelated to the sweep interaction the manifest predicted.
- **4 are `beachcomberPreview`, `beachcomberTrash`, `helmLoad`, `helmSave`** —
  reachable but never invoked, because the sweep clicks buttons while those need a
  row selection then a confirm, or a `<select>` change then a save. **T10 must
  either drive those affordances or move the four to `UNREACHABLE_CHANNELS` with a
  stated reason** — and the latter runs close to the allowlist growth its own
  criteria forbid.

## Advisory findings

1. **The criterion-12 test is slightly weaker than its comment claims.** It
   compares the *post-change* component rendered without the new slots against
   itself rendered with them — not against the literal pre-task component — so it
   cannot detect a change inside the body branch that is invariant across both
   renders. The `git diff` closes that gap (body JSX byte-unchanged), so the
   criterion is satisfied.
2. **The confirm-on-close reasoning holds.** `App.tsx` cannot learn a Helm draft
   is dirty without calling `useHelm()`, whose mount effect issues the scope
   fetch — that would violate criterion 7 directly and break T5's "hook mounted ⇒
   panel open" invariant. Silent discard is a real UX gap, but the fix belongs
   inside T7's panel and is a contract change, **correctly deferred rather than
   smuggled in here**. Carry to Gate 3.
3. **Two nested elements carry region ids, and it resolves unambiguously.** RTL
   `getByTestId` matches the exact attribute string, so `panel-region` hits only
   the layout cell and `panel-region:helm` only the section. Worth one line in
   T10's notes so a future `queryAllByTestId` or `*=` selector does not trip.
4. **Toggle-to-close on an open panel's own button is unrequired but coherent**
   with `aria-pressed` semantics. Untested — the close path is covered only via
   `panelBarClose` and Escape.
5. **The two layout token values remain visually unverified.** jsdom applies no
   stylesheet, so the tests prove the tokens are *referenced*, not that `32px` and
   `880px` are right. Correctly out of scope, since `tokens.css` is T4's file —
   but unexercised until someone runs the app.
6. **The style test covers only the two new sheets**, not the `panelBarRegion` /
   `panelRegion` rules added to `WorkspaceLayout.module.css`. Those additions
   happen to be token-only, so nothing is wrong today.
