## Blocking finding

**B1. Criterion 15's second clause is not met.** The criterion joins two clauses
with "and", and the second — *"were each seen failing first"* — is unambiguous and
admitted unsatisfied.

The reviewer's ruling: **purpose met, letter failed.** The compensating evidence
— an 18-failed first run that exposed three missing `cleanup()` calls and a dead
style matcher, plus two mutation rounds killing 8 and 6 tests — demonstrates these
tests are not vacuous, and the `font-weight:\s*(?!var\()` fix is direct proof that
a dead assertion was found and killed. But red-first is an ordering property of
the writing process, and no after-the-fact evidence can reconstruct it.

### Ranked remediation options, as the reviewer worded them

1. **Accept the compensating evidence at Gate 3 as satisfying the criterion's
   purpose, record the letter-failure as a session decision, change no code.**
   Red-first cannot be recreated for tests that already exist, so a revision round
   could only produce theatre — deleting passing tests to stage a red run proves
   nothing about the assertions that survive. *Evidence: judgment.*
2. **Require the mutation evidence be committed as a durable artifact** — per test
   file, the named mutation and the tests it killed — rather than reported as
   prose. This converts an unverifiable claim into something a later reader can
   re-run, and it matches a habit this directory already has: `no-paths.test.ts`
   and `Helm.styles.test.ts` both ship self-checks proving a rule is not dead.
   *Evidence: repo.*
3. **Spend a revision round re-doing the suites test-first.** Ranked last: highest
   cost, and red-first staged against a known-good implementation is weaker
   evidence than option 2's mutation matrix, because the author already knows
   which assertions will pass. *Evidence: judgment.*

**Orchestrator decision:** revision round on **option 2**. Option 3 is the theatre
the reviewer names. Option 1 changes nothing and defers to the user a decision that
a cheap, real improvement can partly discharge first. The residual letter-failure
survives option 2 — nothing can undo the ordering — and is carried to Gate 3 as a
decision, with the compensation made auditable rather than asserted.

## Advisory findings

1. **The contract promises a side-by-side the frozen action set cannot deliver,
   and T7's classification of it was right.** `helm.ts:251` says the panel "shows
   the current contents **beside** the pending edit", but frozen `HelmActions`
   offers only `reload()`, which replaces the draft, and no action fetching the
   fresh document without replacing it. Criterion 7 never asks for it, T7 satisfies
   criterion 7 as written, and nothing downstream is blocked — so advisory, not
   escalation, is correct. **Carry to Gate 3** as a known contract-prose /
   implementation divergence for a future session.
2. **`Helm.styles.test.ts`'s self-check re-types its patterns** rather than sharing
   constants, so the two can drift; and only four of seven rules are self-checked
   (`rgba(`, `hsla(`, `!important`, `outline: none` are not).
3. **`StringListEditor.test.tsx`'s header overclaims** — it says the suite presses
   "Tab and Enter, never `.click()`", but two lines use `user.click`.
4. **The accessible-name sweep treats non-empty `textContent` as a name**, which
   lets a `<select>` pass on its option text alone. Nothing is currently wrong —
   the scope select carries a real `<label for>` — but the check is weaker than it

## The round-1 artifact, verified rather than accepted

- **The control arm exists and does what it claims.** "reports nothing when the
  injected defect does nothing" runs all nine properties through `mountWith(HelmPanel, noop)`
  — the same post-commit `defect?.(container)` path the real defects use — and
  asserts the failing set is empty. The "notices that…" tests therefore cannot be
  passing on harness noise.
- **Both structural guards are real.** "aims every defect at a property that
  exists" and "leaves no property without a defect to catch" are set-difference
  assertions over the two tables, and the property-name list is pinned to an exact
  nine-element array, so a property cannot be dropped silently.
- **Bidirectionality is genuine, not decorative.** `saveReason` mounts twice and
  fails on either direction — which is why the "Save is dead no matter what"
  defect is caught, since that defect would survive a one-directional assertion.
- **The repeatability claim checks out arithmetically.** The reviewer reconstructed
  it statically rather than mutating the worktree: weakening `declarationRule` to
  `${property}:\s*(?!var\()` makes `\s*` consume nothing so the lookahead sees the
  space, firing on the **clean** samples — 3 "does not cry wolf" failures, plus the
  stylesheet suite reporting those same three against the real CSS = 4, plus the
  neutered defect's "notices that…" = 5. 133 − 5 = 128. Exactly the reported
  5 failed / 128 passed.
- **The `rules.ts` exclusion is sound and does not re-open criterion 2.**
  `rules.ts`, `probes.ts` and `test-fixtures.ts` are imported by test files only
  and none is re-exported from `index.ts`, so nothing excluded is reachable from
  the shipped panel. Both excluded files are `.ts`, not `.tsx`, so JSX cannot
  compile in them at all — structurally stronger than the markup regex the test
  uses. `probes.ts` is **not** excluded and passes the sweep.

## New advisory findings (round 2)

1. **`probes.ts` header is drifted** — it says `HelmPanel.test.tsx` runs the probes

2. **`SOURCE_RULES.length` is asserted `toBeGreaterThan(5)` against six rules**, so

3. **The "no markup in skipped files" needle would miss a `<select>`** or a control

   test reads broader than it checks.
4. **`Helm.module.css` defines no explicit `:focus-visible` styling** — criterion
   12's "focus is always visible" rests on the UA default ring plus the rule
   forbidding `outline: none`. Adequate, but the guarantee is negative rather than
   positive.

## A general lesson worth carrying

Adding `rules.ts` **broke the repo-wide `hygiene.test.ts`** on its first full run,
because two rule *names* contained `rgb()` and `hsl()` — the exact shape that scan
forbids in a non-test renderer file. **A file that states hygiene rules is subject
to them.** Directly relevant to T10, which widens that scan across the renderer.
