## Advisory findings

1. **Closing the Helm panel silently discards an unsaved draft.**
   `resetHelmForReopen` resets to `newHelmState(null)` when the last `useHelm`
   consumer unmounts, dropping `draft` along with `document`. Defensible under
   criterion 11 — that criterion scopes draft survival to the `CONFLICT` path,
   which the implementation honours exactly — and genuinely forced for
   Beachcomber, whose scan-scoped ids answer `NOT_FOUND` after a reopen. The Helm
   case is a judgment call the criteria do not cover. **T9 needs to know its close
   button is destructive to an unsaved form.** A confirm-on-close, or retaining
   the Helm draft across a close, is the follow-up. **Carry to Gate 3.**
2. **`HelmValidationIssue.field` uses `'parseError'`, outside the names the
   contract's doc comment lists.** `validateDraft` emits `field: 'parseError'` and
   `'permissionsDeny'` where `helm.ts:208` documents only five names. The type is
   `string` so nothing breaks, and `'permissionsDeny'` is an obvious omission in
   the comment — but if T7 keys per-field error rendering off those five, a
   `parseError` issue would set `blocked: true` with no visible cause. T7's
   `helmReadOnly` test id likely surfaces it anyway. Confirm at integration.
3. **`HelmView.issues` is computed in the renderer.** Forced —
   `HelmService.validate` lives in main and is not on `HelmApi`, while the frozen
   `HelmView` requires the field. Main remains the authority at save time and the
   store re-checks before invoking, so the two cannot disagree destructively.
   Noted so the duplication is a known one.
4. **`PanelStateStore.refreshScopes()` is public but not on the frozen
   `HelmActions` surface.** Not exported from the barrel and `PanelStateStore`
   is not either, so criterion 1 is not implicated. Still a seam a future caller
   may reach for; a comment marking it internal would be tidier.
5. **The four root headings are the implementer's own copy with no contract or
   repo source.** The contract's own convention is that user-visible copy lives in
   the contract (`PANEL_LABELS`, `PANEL_DESCRIPTIONS`), but that file is frozen and
   T4's, so there was nowhere else to put it. T6 reads `group.heading` off the view
   model rather than the constant, so there is no import-past-the-barrel problem —
   but if T10 asserts heading text it must agree with this file.
