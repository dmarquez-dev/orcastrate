## Blocking finding

**B1. Criterion 5's failed-load half is not met by the shipped system.**
`src/renderer/src/state/panel-store.ts:573-577`.

`loadDocument` clears `document` and `draft` on failure and is shared by
`selectScope` and `reload`, so **no test can make the criterion true.** T10
asserted reality, documented it in a comment, and escalated rather than bending
either side — the reviewer judged that the correct handling, and **the fault is not
in T10's diff.**

**This routes to Gate 3, not to a revision round: the preferred option requires no
change to any file.**

### Ranked options — 1 and 2 are complementary, not alternatives

1. **Amend criterion 5: the draft survives a failed *save*, and a failed *load*
   clears it deliberately.** The criterion over-reaches. Showing scope A's typed
   values under scope B's name is a worse failure than losing them, and
   `renderer-panels.ts:245` already documents reload as "Re-reads from disk,
   **discarding the draft**" — a frozen contract T10 cannot contradict. No code and
   no test change. *Evidence: repo.*
2. **Open a backlog item for the `reload`-failure path specifically.** A user who
   follows the conflict banner's own advice, clicks Reload, and hits `EACCES` loses
   a draft to an operation that wrote nothing — the scope-change rationale does not
   hold there, because the scope did not change. The fix is narrow: keep the draft
   when the failed load's `scopeId` equals the current one. *Evidence: repo —
   `loadDocument` at `panel-store.ts:556` is the single entry point for both
   callers.* Not this session's work; `state/**` is outside T10's ownership.
3. **Change the state layer now.** Not recommended, and T10 agrees: it needs a
   matching revision to T10's assertion, and the design question — which caller
   keeps the draft — has not been decided by anyone. *Evidence: judgment.*

## Advisory findings

1. **Criterion 15's deviation is accepted — ruled deliberate, not incidental.**
   `clickEveryEnabledButton` no longer opens the panels itself; it takes a `skip`
   predicate for the strip buttons and runs again *inside* each opened panel. The
   criterion's operative requirements both hold: the sweep reaches both panels
   during classification, and attribution is explicitly accounted for (sentinels
   asserted pairwise-distinct, plus a test showing Helm stays silent while only a
   Beachcomber channel fails). Doing it literally would let DOM order decide
   mid-sweep whether the remainder ran against the workspace or a panel —
   **defeating the criterion's own attribution goal.** Optimising for the heading
   was right.
2. **All four out-of-ownership findings are real; the reviewer reproduced three.**
   (a) Exactly six raw declarations, in `shell/EmptyWorkspace.module.css` (×2) and
   `shell/WorkspaceLayout.module.css` (×4); `beachcomber/` and `helm/` are fully
   tokenised. `--oc-weight-*` offers regular/medium/bold only, so `font-weight: 600`
   **has no token** and fixing it is a visual decision, not a swap. (b) The
   `HelmNotices` duplicate-sentence defect is real. (c) `helm/rules.ts:7-8` states
   the lookahead bug backwards — it says the broken form "matches nothing", but it
   returns `true` on a tokenised declaration, i.e. it fires on **clean** code. The
   shipped pattern is correct; only the prose is wrong. (d)
   `tests/unit/store/errors.test.ts` fails under `--sequence.shuffle` at line 119
   with `provoked` empty — pre-existing sub-session 1 file. **All four belong in
   the backlog.**
3. **Two pins will fail when the defects they pin are fixed** —
   `PRE_TOKEN_SHELL_DECLARATIONS` and the `toHaveLength(2)` on `HelmNotices`. That
   is the intended two-sided design, but each fix carries a mandatory edit to
   T10's file. Name the coupling in the backlog items so it is not a surprise.

   none of the other five suites changed it reduces to "none needed a change", and
