## Advisory findings

- **A1 — `EACCES` is exercised through an `ENOTDIR` proxy.** `roots.test.ts:73-94`
  puts a plain file where `shell-snapshots` belongs rather than forcing a
  permission fault. The justification holds (no portable way to force `EACCES` on
  Windows without ACL manipulation), and `service.ts:227-236` branches only on
  `ENOENT` vs everything-else, so `EACCES` provably takes the same path the test
  exercises. On the record rather than discovered later.
- **A2 — the frozen contract's `refused` comment no longer describes the shipped
  behaviour.** `src/shared/contracts/beachcomber.ts:213` says `refused` covers ids
  "blocked by a Pod, or unknown to this scan", but criterion 6 and the same file's
  own `BeachcomberService` doc (`:301-306`) and header (`:43-46`) require an
  unknown or stale id to throw `NOT_FOUND`. T2 correctly followed the criterion
  and the more specific statements, and correctly did not edit the frozen file.
  The stale half-sentence is the outlier and **is worth an amendment at Gate 3**,
  since T1, T5, T6 and T10 all read that comment — a consumer coding to it would
  wait for a `refused` entry that never arrives.
- **A3 — recursive `sizeBytes` is asserted loosely.** `roots.test.ts:129-130`
  computes `entry.sizeBytes - 15` and asserts only `> 0`, which still passes if
  the 15 nested bytes were never counted. Recursion is genuinely covered by
  `fileCount === 3` on the same tree, so the criterion holds, but pinning
  `sizeBytes` to its exact total would make the assertion say what it means.
- **A4 — Pod blocking compares against `displayPath`, which may be a guess.**
  `service.ts:147,188`. For a `projects` entry with no cwd-bearing record the
  comparison key is the decoded guess, so a Pod holding that directory's *true*
  path would not block it. This matches criterion 7 as written ("resolved cwd"),
  and the failure is bounded — trashing removes the `~/.claude/projects/<dir>`
  state, not the Pod's working directory — but it is the one place where the
  decode ambiguity leaks into a safety check rather than into a label.
- **A5 — `../ipc/errors` drags a large runtime graph in for one class.**
  `service.ts:67` imports `IpcFailure`, and `errors.ts` imports `../pod` and
  `../store` at runtime. Harmless today, and criterion 1's scan is satisfied as
  specified (direct imports), but a leaf error module would keep the isolation
  the directory header claims true transitively as well as directly.
