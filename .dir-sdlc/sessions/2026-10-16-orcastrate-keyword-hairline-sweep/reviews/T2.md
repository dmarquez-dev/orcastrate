### The two-in-one control — it holds, and the probe resolved in the implementer's favour

The concern raised at dispatch was that the near-miss might have passed the census because the
reader skipped its line for an unrelated reason rather than because of the term anchor. The
reviewer separated those two explanations: it placed a **bare `thick` at the exact line position
the near-miss occupied** (`.marker`, line 139) and the census flagged it at exit 0. So that line
is squarely where both instruments read, and the near-miss's pass is caused by the term boundary
and nothing else. In the combined run, the near-miss sits at line 140, present and unflagged,
while 139 is the single hit.

It then exercised the live `borderValues` + `keyworded` predicate against the contract's **full**
declared sample sets on a scratch copy, with an injector that asserts its own landing — the
declaration count moves 3 → 4/5 and it throws if the replace is a no-op. **That instrument was
itself positive-controlled, and needed to be:** the reviewer's first attempt silently failed on
CRLF and reported twelve false passes.

- All five `KEYWORD_MUST_FLAG` shapes flag: `border: medium`, `border-top: thin`,
  `border-width: thick`, `border-block: thin`, and the shipped `border: thin` form.
- All seven `KEYWORD_MUST_PASS` shapes pass, including the load-bearing `var(--oc-border-thick)`
  in both shorthand and `border-width` position, and `--oc-border: thin`.
- **Boundary class:** `[^-\w]` treats `-` as an identifier character on both sides, as
  `KeywordWidthMatchShape` requires. Ten cases behaved as declared, including the right-hand side
  in isolation (`thin-x`, `thinner` not flagged) and `_` (`thick_rule` not flagged).
- **Property alternation:** it does **not** reach `border-style` or `border-color`. As shipped the
  matcher reads exactly 3 declarations, all property `border`; `.action:disabled`'s
  `border-style: dashed` (`:110`) and `.deny`'s `border-color: var(--oc-danger)` (`:115`) are never
  read, because the optional group cannot consume `-style`/`-color` and the required `\s*:` then
  fails. `border-radius` is excluded the same way. The implementer's own warning about this trap
  was well founded and its matcher avoids it.
- **Termination hazard:** `grep -n ')solid'` → no match, exit 1; `grep -cE 'var\(--oc-border-hairline\) solid '` → 3.

### Advisory findings

No options attached — the reviewer supplies them for blocking findings only.

**A1 — "anywhere" in the new test name is broader than the predicate's scope.**
`PermissionCards.styles.test.ts:59`. The predicate reads only border/outline **property**
declarations, so a bare `thin` in a custom-property declaration would stand while the test stayed
green — and the frozen contract **requires** exactly that (`KEYWORD_MUST_PASS` lists
`--oc-border: thin`), which the reviewer confirmed both instruments honour. So the name promises
coverage the contract forbids the test from having. The reviewer weighed this against criterion 8
and deliberately did not make it blocking: the name's first clause establishes border widths as
its subject, the narrow reading is the natural one in context, and the only over-promised case is
one no reader could be misled about a real defect by. A wording like
`…and no bare width keyword in any border width` would close it.

**A2 — the test predicate and the contract's census command disagree on `_`.** The test uses
`[^-\w]`, which excludes `_`; the contract's census grep
(`contracts/keyword-hairline-sweep.ts:30`) uses `[^-[:alnum:]]`, which does not — so `_thin`
would flag in the census and not in the test. **Carried to T4, which owns the shipped matcher.**

> **Orchestrator's measurement on A2.** The divergence is real but **unexercised in this tree
> today**: the only underscores in any renderer `*.module.css` are inside comment prose
> (`pods/PodBar.module.css:199` `BYPASS_PERMISSIONS_WARNING`,
> `transcript/Transcript.module.css:218` `tool_use`, `:364` `lane_closed`), and none is a CSS
> identifier in a declaration value. The search instrument was positive-controlled against a
> planted `.a { border: _thin solid red; }`, which it matched, so the absence is measured rather
> than assumed. T4 decides whether the two readers should agree; it is a consistency question,
> not a live defect.
