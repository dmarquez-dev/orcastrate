### The reach-note question, resolved

The contract's reach note and the implementer's own pre-written note both said the three
permission-card sites need a live `claude` process. **They do not.** The main process can send the
app's own `push:laneChanged` and `push:permissionRequested`, and the card renders; no `claude`
process ran, and the absent thing is the originating child process.

The implementer disclosed this and offered that, if a synthetically-pushed card does not count as
"measured on screen", those three revert to "unreachable with a pre-written reason" — which
criterion 4 explicitly permits, so the criterion passes either way.

**The reviewer recorded its own judgment, agreeing with the orchestrator's reading:** the
measurement is of shipped CSS over shipped DOM in the real window, a `claude` child process does
not participate in layout, so this is measured on screen. **What was wrong was the reach note, in
the favourable direction**, and the findings state the route plainly rather than letting it pass
unremarked. `screenshots/keyword-sweep/04-permission-card.png` shows the card, its deny-reason
input and its Allow / Allow always / Deny row.

### On the `as string` rule, which could not apply

`as string` is TypeScript syntax and a syntax error in a `.mjs` file Node executes directly. The
one new `matchAll` uses indexed access `m[1]`/`m[2]` with a comment stating both groups are
unconditional in the pattern — the safe half of T1's rule. **The reviewer verified the scope
claim:** `tsconfig.node.json` includes only `electron.vite.config.ts`, `vitest.config.ts`,
`src/main`, `src/preload`, `src/shared`, `tests`, `probe`; `tsconfig.web.json` only
`src/renderer/src` and `src/shared`. Nothing under `.dir-sdlc/` is in either program, and neither
sets `allowJs`, so a `.mjs` could not be checked even if it were reachable. The comment's claim is
true of the pattern `/_([A-Za-z0-9]+)_([a-z0-9]{5})_\d+/g`.

   Worth widening in the next driver rather than here.

   > `~/.claude/settings.json` has mtime `Aug 17 11:37` and sha256 `2ce33958…`, matching what the
   > run recorded; `settings.json.prelaunch` is dated **Aug 20**, two months before this session.

   a census that silently scans the wrong tree and reports confidently either way. Not T5's file

   > **The orchestrator hit this and it produced an accidental positive control.** Running
   > `vitest run --root <worktree>` from the main checkout scanned the main checkout at `6914e49`
   > and failed with exactly **6** offenders — the six unconverted `thin` declarations. So T4's
   > widened predicate flagged precisely the pre-conversion population and nothing else, on a real
