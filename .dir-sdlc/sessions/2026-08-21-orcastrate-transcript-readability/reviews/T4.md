## The watched failure by substitution — ruled equivalent, and verified independently

T4 has no git access, so it could not check out `b2c3caf`. It planted `b2c3caf`'s **actual output
strings** as the constants and ran against fixed code.

**The reviewer did not take this on testimony.** It read
`b2c3caf:src/renderer/src/transcript/TranscriptFilterToggle.tsx` directly and confirmed the old
code returns `` `Show ${hiddenCount} hidden system events` `` and `` `Hide ${hiddenCount} system
events` `` — rendering at n=1 exactly the two strings T4 planted. The premise the substitution
rests on is verifiable from history, and it was verified.

**Its ruling: this is a *stronger* shape than a deleted probe, structurally.** A deleted probe
leaves the reviewer with only the implementer's testimony; a substituted *input* leaves the old
input recoverable from history and therefore checkable by someone who was not there. The one
residual gap — it proves the assertion discriminates the string, not that the old app routed that
string to that button — is closed from the other side, because the same test asserts the label
through `getByRole` on the live pane **and** cross-checks `filterToggleLabel('conversation', 1)`
directly, pinning producer and page together. *"I would accept this form again."*

## The two new hygiene rules — both fire

Reasoned from shipped source rather than planted, since planting would mean writing outside the
reviewer's ownership. The reasoning is decisive: `filesUnder` is an **unfiltered recursive walk
with no directory exclusions**, so a probe file under `__tests__/` is reached by the
`/\.(ts|tsx|css|html)$/` filter; a literal `0x08` makes `controlByteReport` return non-null and
the `toEqual([])` fails; a contiguous retired literal in code in a non-exempt file does the same.
Both rules are additionally **self-proved against synthetic samples in their first `it`**,
including the `\b`-versus-`0x08` near-miss that caused the incident.

**Noted approvingly:** both rules carry `expect(files.length).toBeGreaterThan(100)` before
reporting clean — the exact defence against the "rule reports clean for a path that does not
exist" failure.

**Design verdicts, all three upheld:**
- **Not banning non-ASCII is correct.** The box-drawing and ellipsis characters are live and
  load-bearing in this tree; a non-ASCII ban would be red the day it landed. Sub-U+0020 minus
  `\n\t\r` plus U+007F is the right cut, and tolerating `\r` matters on this Windows checkout.
- **Stripping comments is correct.** A test id can only do harm from a selector, a selector is
  code, and every other rule in the file draws the same line. Refusing it would forbid the docblock
  that explains the deletion.
- **The exemption self-check works.** It requires `LaneRail.test.tsx` to be in the walked set *and*
  to still carry the literal after `stripComments`. Deleting the line, the file, or moving it into
  a comment turns the exemption test red with a named message. A real staleness guard. One gap in A2.
