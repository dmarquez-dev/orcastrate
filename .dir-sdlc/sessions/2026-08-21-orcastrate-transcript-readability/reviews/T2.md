## The backspace byte — a failure mode with no test-level detector

T2's scripted edit wrote a **literal `0x08`** into `Transcript.styles.test.ts` instead of the two
characters backslash and `b`. **The regex still behaved correctly, every test stayed green, and
nothing in the suite would ever have flagged it** — only an `od -c` revealed it. T2 found it,
repaired it, and scanned its 16 files.

The reviewer confirmed the repair at byte level (`0x5C` then `0x62` at both escape sites; no `0x08`
anywhere) and **ran its own scan** across every `.ts`, `.tsx` and `.css` under all of `src/` for
control bytes outside newline, tab and carriage return — **zero hits**, independently confirming the
orchestrator's repo-wide result.

Unlike the eleven vacuity catches, **no test could have caught this, because the tests were not
wrong.** The only defence is reading the bytes.

## Advisory

1. **A6 — probe D does not exercise the shipped guard, and must not be cited alongside A–C.** It
   uses `node:assert` `deepStrictEqual` over a **hand-copied list with no link to the real
   `TEST_IDS`**; had the copy drifted it would still print FIRED while proving something about two
   arrays it invented. What it shows is close to a tautology — a 32-element array is not deep-equal
   to a 31-element one. Probes A–C were load-bearing because the two guard spellings are a genuine
   vacuity fork; `toEqual` on arrays has none. **The real risk was a wrong list, which probe D is
   structurally incapable of detecting.** Verified by other means instead.
2. **A7 — a claim relayed by the orchestrator was wrong.** `margin-inline-end:0;` is **not** a case
   the old pattern would have got wrong: with no whitespace the `\s*` matches empty, the lookahead
   lands on the zero, and the old pattern was silent there too. Its single failure was the **space**
   form. The test case is still worth keeping; it is not a regression case.
3. **A8 — the new matcher false-positives on `0px`/`0em`.** Zero and `p` are both word characters,
   so the word-boundary lookahead fails inside `0px` and the pattern fires on a margin that is in
   fact zero. `0%` is correctly silent because `%` is non-word — an inconsistency that will read as
   arbitrary. Latent only: no such declaration exists in the file.
4. **A9 — `systemEventPronoun` is not re-exported from `index.ts`** while its sibling
   `systemEventNoun` is. Nothing consumes it outside the module; noted because the two were
   introduced as a deliberate pair.
5. **A1 (round 0, fixed in round 1)** — the pronoun stayed plural at n=1. Fixed via
   `systemEventPronoun`, with **bidirectional** assertions confirmed real: the n=1 test also asserts
   the plural pronoun is absent and n=2 asserts the singular is absent, so a half-fixed sentence
   fails in either direction.
6. **A5 (round 0, fixed in round 1)** — the matcher that did not mean what it said. The three proof
   assertions now run **immediately before** the assertion they guard, in the same test.
7. **A2 — `tool_use`'s label changed from `Tool: <name>` to `Tool`**, the name having moved into the
   summary. Judged **in scope** (keeping both would print the name twice). `You`, `Claude` and
   `Tool result (error)` unchanged character for character; no consumer of the old string exists.
   **A user-visible copy change worth a line at Gate 3.**
8. **A3 — `summarizeToolCall` returns the counted fallback for an empty-or-whitespace string
