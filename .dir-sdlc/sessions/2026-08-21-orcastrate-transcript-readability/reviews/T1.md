## The self-audit, confirmed

T1 reported finding one of its own tests passing for the wrong reason. The reviewer verified
every part of that account: the replacement assertion discriminates, the microtask reasoning is
correct at source, and the dead test is genuinely deleted rather than renamed. This is the
seventh vacuity-class catch in this project and the second found by an implementer in its own
work.

## Advisory

1. **Two tests sit under a misleading `describe`.** `'the runner observes the appended row
   already in the store'` and `'an unknown Pod appends nothing and still throws NOT_RUNNING'`
   are inside `describe('criterion 4: a Pod with no Matriarch lane still sends')`
   (`tests/unit/pod-manager/user-prompt.test.ts:44`) but pin criterion 2 and the
   `#requireSession` ordering. In-file comments say so; the label will still mislead the next
   reader mapping tests back to criteria.
2. **A residual vacuity the reviewer found in criterion 7.** `expect(withSend).toEqual([typed,
   ...baseline])` is vacuously satisfiable for a fixture whose replay ingests nothing — both
   sides collapse to `[typed]`. Only `01-parallel-dispatch` carries a hard positive row-count
   guard. A single `expect(baseline.length).toBeGreaterThan(0)` for the fixtures known to carry
   Calf prompts would close it; `04-orphaned-calf` legitimately has zero.
3. `#suppressEchoes` returns the same `batch` reference on the empty-pending fast path, while
   `suppressEchoedUserPrompts` returns `[...batch]` on all its early returns. Harmless —
   nothing downstream retains the array — but the aliasing differs for no stated reason.
4. `tests/unit/ipc/helpers.ts:157-158` — the `now:` default line will likely reflow under a
   formatter. Cosmetic.
5. **Which evidence rests on the orchestrator's run rather than on this review:** criterion 1's
   watched-failure vitest output and criterion 9's before/after counts live in the task report,
   not in the diff, so the reviewer could not verify them from the artifacts it was handed.
