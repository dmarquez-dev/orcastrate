### Blocking finding

**The suite-wide empty-batch guard in `afterEach` is a test that cannot fail** — `close-pod-lane-sweep.test.ts:36-51`. Violates criterion 4's clause "no `podEvent` push with an empty `events: []` is recorded at any point in the suite".

The input that would have to occur for it to go red cannot occur. The harness wires the manager through `createPushes`, and `src/main/pod-manager/pushes.ts:35-37` already drops empty batches **before** `send`:

```ts
podEvent(payload) {
  // Contract: "Batched in `seq` order. Never empty."
  if (payload.events.length === 0) return;
```

*(Independently verified by the orchestrator.)*

**Reviewer-reproduced, injected defect:** inserting `this.#push.podEvent({ podId, events: [] });` immediately **above** the `stoppedLaneIds.length === 0` guard leaves all 10 tests passing, twice in a row.

The guard's own comment — "a push hoisted above the `stoppedLaneIds.length === 0` guard fails here wherever it was added" — is therefore false of the code it sits in. The production behaviour is correct and belt-and-braces (the `createPushes` filter, plus placement below the guard); what fails is the assertion the criterion asked for.

Remediation options, best fit first:

1. **Record pushes at the `Pushes` boundary rather than after `createPushes`'s filter.** In `tests/unit/pod-manager/helpers.ts` (T1-owned), have `makeManagerHarness` wrap the `Pushes` object so each method's argument is recorded before delegating to `createPushes`. The `afterEach` guard then observes what `#stopRunningLanes` actually called, and goes red on a hoisted empty push — making criterion 4's clause literally true. *Evidence: repo — `helpers.ts:270-273` is the single recording point; every other suite in the directory shares it, so their push counts must be re-verified.*
2. **Drop the `afterEach` loop and assert the invariant where it can fail:** a direct test that `createPushes` sends nothing for a `podEvent` with `events: []`, with placement below the guard already covered by the idempotence counts. Cheaper and honest, but moves the assertion off `#stopRunningLanes`. *Evidence: repo — `pushes.ts:35-37`.*
3. **Keep the guard as defence-in-depth and correct its comment**, stating that `createPushes` already filters empties and this is a second net. Lowest cost; leaves an assertion that can never fail in the file. *Evidence: judgment.*
