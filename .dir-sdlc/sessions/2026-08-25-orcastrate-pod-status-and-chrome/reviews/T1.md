## Advisory findings

- **`migration-frozen.test.ts` shells out to `git show` at run time**, so the guard is unavailable wherever git history is. In a shallow clone (`actions/checkout` defaults to `fetch-depth: 1`) or an exported tarball with no `.git`, `execFileSync` throws and the three cases go **red rather than skipped** — a loud false failure, which is the better of the two failure modes. This repo has no `.github/workflows` today, and criterion 3 explicitly asked for migration-2's established shape, which is this shape. If shallow-clone CI ever lands, the durable fix is committing the shipped renderings as a fixture rather than reading them from history.
- **`migration-2.test.ts:41-120` still carries its own migration-1 byte-identity test**, now fully subsumed by `migration-frozen.test.ts`. Two copies of one guard drift independently.
- **`migration-frozen.test.ts` covers migrations 1-3 only.** Migration 4 has no shipped blob yet, correctly — but nothing records that its hash must be added once this branch merges, which is precisely the omission that made migration 1's pin necessary.
- `schema.ts` renders LF while the worktree checks out CRLF, so `git diff` warns on every touch. Pre-existing, not introduced here.
