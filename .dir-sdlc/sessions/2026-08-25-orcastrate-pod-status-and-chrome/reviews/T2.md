## Advisory findings

- **The `&&` fold at the `#closeLaneRow` call site is correct but reads as a side effect hidden in a condition** (`pod-manager.ts:1238`). Short-circuit order does what it appears to, and the narrow is load-bearing beyond style: removing it is a *type error*, since `LaneClosedPayload.status` has three members and the callee takes two — so `tsc` enforces criterion 6 here rather than a test. An early-skip form would separate guard from mutation, but that is preference, not a criterion.
- **The empty-sweep early return is sound.** No consumer requires an unconditional `laneChanged`: the push replaces the rail wholesale, so with zero rows changed it would redraw identical content. `reconcileStartup` sets the precedent. Recorded as an assumption rather than acted on.
- `expect(matriarch?.endedAt).not.toBeNull()` would also pass on `undefined`; the adjacent status assertion forecloses that, so it is redundant rather than weak.
- Criterion 2's single-`appendMany` test necessarily uses the write spy, since batching is not observable from rows. The "read the events back" half is satisfied separately by the seq test. Noted so it is not mistaken for the mock-spying criterion 5 forbids.
