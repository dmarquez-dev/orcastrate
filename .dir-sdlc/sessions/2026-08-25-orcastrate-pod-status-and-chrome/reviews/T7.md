# T7 — End-to-end proof that stopping a Pod reads as Stopped

Round 1. Verdict: **PASS**, 0 blocking, 3 advisory.
Criterion 3 recorded **not met by user decision**, not by implementer fault.

## Per-criterion verdicts

1. **Met.** Imports the real `PodManager`/`createPushes` and `openEventStore(':memory:')`, wired through `EVENT_CHANNELS` by name; the only double is the inert `PodRunner`. 6 tests pass. *red step, reviewer-reproduced* — **probe A** (commenting out `this.#stopRunningLanes(podId)`) gives `3 failed | 3 passed` with `expected '…' to contain 'Stopped'` and `Received: "matriarch (Matriarch, pinned to top)No descriptionRunningElapsed 1m 30s"` — byte-identical to the implementer's report, and the reported defect verbatim. **Probe B** (making `elapsedMsOf` ignore `endedAt`) gives `2 failed | 4 passed` with `expected 'Elapsed 0s' to contain '1m 30s'`, confirming the duration assertion is independently falsifiable, which probe A alone did not show. Both production files restored.
2. **Met.** Positive guards before every equality assertion but two (see advisory), including `elapsedText.length > 0` — which matters because two empty strings are byte-identical, so "the duration did not change" would otherwise hold for a row rendering no duration. *reviewer-reproduced*: under probe B the row rendered `Elapsed 0s`, not empty, so the length guard was not what fired — the content assertion was.
3. **NOT MET — by user decision.** The criterion's premise is false: `lane_closed` is in `PLUMBING`, not `CONVERSATION`, so criteria 3 and 4 contradict each other as written; and independently `#stopRunningLanes` pushes only `laneChanged`, never `podEvent`, so the event never reaches the renderer in either mode. Both verified by the orchestrator, escalated as E3, and carried to the backlog with the session closed at its agreed scope. **Narrow check passed:** the file contains **no** assertion pinning the empty-transcript behaviour as correct — no query over transcript rows, no absence assertion, no toggle flip. The only two `toEqual([])` are over the **store**, not the view. It asserts the durable record instead: exactly one `lane_closed`, correct `laneId`/`payload`/`createdAt`, and `LANE_STATUS_LABEL[status.status] === 'Stopped'` read from the payload the sweep wrote rather than from a literal. Nothing locks the defect in behind a green suite.
4. **Met.** `git diff --stat 25d241f -- transcript-filter.ts` is empty. *The reviewer initially saw an md5 mismatch and correctly diagnosed it as a CRLF artifact of `git show` rather than a change.* Membership of `thinking` in `PLUMBING_EVENT_TYPES` is pinned by an assertion falsifiable by the exact edit it guards.
5. **Met.** *reviewer-reproduced* — both typecheck projects exit clean; `npm test` reports `Test Files 132 passed (132)`, `Tests 2020 passed (2020)` from the runner's own totals.
6. **Met.** *reviewer-reproduced* — `--sequence.shuffle` gives `1 failed | 131 passed`, the single failure being the known order-dependent `tests/unit/store/errors.test.ts`. `git status` confirms that file was not touched: named, not opportunistically fixed.
7. **Met.** A grep for sleeps, wall clock, network, ports, locale and time-zone reads returns only imports and prose. `vi.useFakeTimers({ toFake: ['Date'] })`; every instant a UTC literal; store is `:memory:`.
8. **Met.** One new test file. No `src/main` or non-test renderer file touched. Both boundary cases were escalated rather than edited.

## Additionally verified, as asked

- **No `'stopped'` is seeded anywhere in the fixture.** The only two `'stopped'` literals are assertions on what `closePod`'s sweep computed; a helper proves every lane starts `running` with `endedAt === null`. Had the fixture seeded it, the test would have proved only that the fixture was typed correctly.
- **The live control Pod works.** The untouched Pod reads `3m 00s` then `24m 00s` at the same two instants the stopped row is re-read, and neither `'1m 30s'` nor `'24m 00s'` is a substring of the other — so a build that failed to stamp `ended_at` fails `toBe(frozen)` rather than passing on a frozen clock.

## Advisory findings

- **Two negative assertions lack a positive guard.** `persistedEvents` lacks the `length > 0` guard its sibling `persistedLanes` carries. Not blocking: the plausible defect — a `readEvents` ignoring `podId` — makes the assertion **fail**, not pass, and the adjacent guarded `persistedLanes` proves the kept Pod is populated. Adding the guard would close the letter of criterion 2.
- **Probe A is an approximation.** It reintroduces the defect by disabling the fix rather than checking out the pre-session tree, which also lacked migration 4's `'stopped'` and the renderer token. Faithful enough — the observed symptom is exactly the reported defect — but recorded as an approximation rather than a true pre-session run.
- **An unexplained constant.** `waitFor(..., { timeout: 4000 })` depends on the provider's real-timer tick to repaint the live control lane. Not a sleep, and not flaky across three runs, but the magic `4000` sits oddly in a file whose other constants are heavily reasoned.
