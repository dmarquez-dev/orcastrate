## The Orphaned test — correct, and the guard discriminates

The suite asserts the **measured** condition: no terminal `task_updated` and no
`task_notification` anywhere in `04`; the lane opened by `system/task_started`
and correlated by `tool_use_id`; the lane still `running` when `result` arrives
(replayed line-at-a-time so the state *at* the result is observable); zero
in-turn closes; `onTurnBoundary()` produces exactly one `orphaned` close with the
matching laneId; idempotent on a second call.

The anti-vacuity guard — *"the dispatching tool_use IS answered"* — locates the
dispatch by scanning and requires `toolResultLine > 0`, so a future capture that
stopped answering it would fail loudly and tell the reader the naive assertion
had become live. The `03` positive control asserts `terminalLine < resultLine` on
the capture itself, then requires the close **on** the terminal `task_updated`
and **absent** on the dispatching `tool_result`. M1 confirms empirically that a
naive router flips both simultaneously.

## Independence from T5's tests

Every kill above came from T6's files alone. The suite is fixture-derived, not
implementation-derived: expected lane assignment and the dispatch chain are
recomputed from the raw captures, corruption sites and dispatch lines are located
by scanning rather than hardcoded, and every counted expectation is read from
`findings.json`. It touches only the frozen contract's surface. One genuine gap:
inline mode (A3).

## Advisory findings

- **A1** — `hygiene.test.ts` uses a flat `readdirSync`, so a test added under
  `tests/router/<subdir>/` would run in `npm test` but escape every criterion-4
  and criterion-7 rule.
- **A2** — The banned-token lint is substring-based and defeatable by the same
  fragment-concatenation trick the file itself uses, by a template literal, or by
  a dynamic import. The **import allow-list** is what actually constrains
  reachability; the token list is a tripwire against accidents and should say so.
- **A3** — **`inline` routing mode is uncovered by T6.** Mutant M8 survived all
  202 tests; only T5's own file covers inline. Not required by any acceptance
  criterion, but it is the one place the "survives deletion of T5's tests"
  property fails.
- **A4** — `the router reports the mode findings.json recommends` is
  near-tautological (constructs with `mode: recommended`, asserts `.mode ===
  recommended`). Criterion 6 is met by the sibling assertions — the derivation
  rule, the hard drift guard, and the behavioural 3-distinct-lanes check on `01`.
- **A5** — **The design spec still carries the disproven rule.**
  `docs/superpowers/specs/2026-08-18-orcastrate-design.md` states the
  `tool_result` close rule at **lines 40, 118, 292, and 303**. `findings.json`,
  `docs/protocol-findings.md`, the router, and this suite all implement the
  corrected rule. **The spec is the last live copy of the wrong rule**, and a
  future reader will trust it. Concrete Gate 3 amendment. The frozen
  `fixture-corpus.md` §1 one-line description of `04` is also wrong but cannot be
  amended; its superseding note lives in `findings.json`.
- **A6** — `TERMINAL_STATUSES` in `lifecycle.test.ts` independently restates the
  router's `isTerminalTaskStatus`. The independence is correct for an acceptance
  suite; note only that a router recognising a status absent from this list would
  fail with a confusing message rather than a pointed one.
