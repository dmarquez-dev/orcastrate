## The registered/materialized split — verified adversarially

The reviewer enumerated **every** `out.push(...)` and classified its lane source.
Four paths bypass `emit()` — `routeSystem`, `routeResult`, `rate_limit_event`,
`malformed()` — and all four are hardcoded to `matriarchLaneId`, which the
constructor seeds `materialized: true`. No Calf id can reach them. `materialize()`
pushes `lane_opened` itself; `closeLane()` materializes before `lane_closed`, so
even a lane whose dispatching `tool_use` never arrived is announced before its
close. The only lane-id sources feeding `emit()` are `resolveLaneId()` (which
validates `states.has`) and a just-created state.

**Conclusion: construction, not fixture luck.** The cross-fixture `known`-set test
would catch a regression but is not what makes the property true.

## Close logic — read from the code, not the tests

`closeLane` has exactly two callers: `closeByAgentId` (reached only from
`onTaskUpdated`/`onTaskNotification` with a terminal status) and
`onTurnBoundary`. `routeBlock`'s `tool_result` case contains **no close call
under any condition**.

- `03`: the terminal `task_updated` (line 16) produces the single `done` close;
  the dispatching `tool_result` (line 18) produces none. Asserted both ways.
- `04`: zero closes during replay — line 6's "Async agent launched successfully"
  ack produces none — Calf still `running` at stream end, `onTurnBoundary()`
  yields exactly one `orphaned` close, second call returns `[]`.

**T6's Orphaned test on `04` cannot pass vacuously.** Terminal-status matching is
a list broader than the observed `completed`, which errs safe: an unlisted status
leaves the lane running and `onTurnBoundary` still orphans it.

## Advisory findings

Carried to Gate 3. No options attached.

- **1** — `emit()` skips materialization for an unknown `laneId` and pushes
  anyway. Unreachable today, but the failure mode is a silently unannounced lane
  rather than a loud error. Falling back to the Matriarch would make criterion 7
  total rather than reachability-dependent.
- **2** — `purity.test.ts` blind spots: non-recursive `readdirSync` misses a
  future `./sub/helper.ts`; import regexes match only quoted literals so
  `import(variable)` is invisible; `FORBIDDEN_GLOBALS` omits `performance.now`,
  `crypto.getRandomValues`, `Date.UTC`, `process.uptime`. Cheap fixes; the
  byte-identity test partly compensates.
- **3** — **`system/task_progress` routes away from its own Calf.** The reviewer
  judges the blanket "all `system` to the Matriarch" rule the wrong default. That
  message carries `tool_use_id`, `subagent_type`, `last_tool_name`, and per-Calf
  `usage` — real per-lane telemetry with a correlation key in hand. The result is
  that `04`'s background Calf has no content events at all while the Matriarch
  accumulates progress lines about a lane the user is viewing elsewhere. The
  rationale is precise for `task_started` (routing it to the Calf would force
  materialization before parent and depth are known) but over-generalized to
  `task_progress`, which arrives post-materialization in every fixture. Suggested
  refinement: route correlatable post-materialization `task_progress` to
  `byToolUseId.get(tool_use_id)` with a Matriarch fallback. **Sub-session 2
  input**, since the right answer depends on how the Calf pane renders.
- **4** — In inline mode `lane_opened` carries a Matriarch `laneId` with a Calf
  payload. Correct per contract, but consumers must key lane persistence off
  `payload.lane.id`, never `event.laneId`. **T7 handoff note.**
- **5** — **`agentId` backfill has no trigger.** Escalated as **E4**.
- **6** — Unrecognized top-level message types become `malformed`. Correct for
  the planted `quantum_flux`, but a real future SDK type (e.g. `stream_event`
  under `includePartialMessages`) would flood the transcript. Speculative today —
  nothing in the repo enables partial messages.
- **7** — `KNOWN_MESSAGE_TYPES` is exported but unused, duplicating `route()`'s
  switch without being wired to it, so the two can silently diverge.
- **8** — `system` and `result` events store the raw message twice (`data` and
  `raw`), doubling persisted bytes for every system event — `system/init` carries
  the full tools array. Size consideration only.
