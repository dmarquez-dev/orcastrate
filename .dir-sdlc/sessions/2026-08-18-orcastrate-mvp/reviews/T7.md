## Blocking findings — both fixed in round 1

**B1 — every `lane_opened` was restamped off its own Calf onto the Matriarch.**
`#routeLane` ran before `#ensureLaneRow`, so at the moment a `lane_opened` was
routed its lane row did not yet exist, and the unknown-lane branch redirected it
to the Matriarch. Reproduced: `lane_opened seq 3: eventLaneId "id-2"(matriarch)
payloadLaneId "id-3"`. Two consequences — a renderer filtering by `event.laneId`
would show the Calf's opening marker in the Matriarch's stream, and the drift
warning fired on every Calf in every turn, permanently masking the regression it
was written to catch.

**Fixed via option 1**, handling `lane_opened`/`lane_closed` off `event.payload`
before `#routeLane`. The implementer rejected option 2 (two-pass persist) and the
reviewer **accepted that reasoning as better than its own ranking**: pre-materializing
every lane row would make the unknown-lane branch dead code, silently absorbing a
`LaneRouter` contract violation that the FK would no longer catch either. Option
1 fixes the ordering at its source and leaves the detector armed;
`expect(h.logged).toEqual([])` over four fixtures converts armed into verified.

**B2 — `#pending` keyed by bare `requestId`, colliding across Pods.** The SDK
scopes `requestId` to one worker connection and each Pod is its own worker, so two
Pods could share one. Reproduced: one map entry for two live prompts, B's answer
deleting A's, A permanently unanswerable and unreachable by its own close sweep.

**Fixed via option 2**, moving the map onto `PodSession`. The reviewer confirmed
the deleted `entry.podId !== req.podId` guard is **structurally unreachable**, not
merely redundant: the only writer closes over one session, the only reader goes
through `#sessions.get(req.podId)`, and `#settle` deletes through `entry.owner`.
Outliving the session is closed too — every path that drops a session aborts its
prompts first.

## A third defect, found by an advisory rather than by the audit

The round-1 review audited criterion 3 for escape paths, found none, and noted as
a *test-strength advisory* that every failure class threw synchronously. Acting on
that advisory found a real hole: **`permission:respond` was a non-`async` block
arrow calling an async method with neither `await` nor `return`**, so the promise
escaped the wrapper's `try` — a rejection would have become a silent `{ok:true}`
plus an unhandled rejection in main. Production was unaffected only because
`respondPermission` is synchronous today.

**Correction recorded.** The implementer reported four affected handlers; the
reviewer verified only `permission:respond` dropped a promise. `pod:delete`,
`pod:close`, and `pod:interrupt` were `async` block arrows that awaited —
discarding the value but not the rejection, so they already returned `{ok:false}`
correctly. The rewrite to expression arrows is still right because it removes the
shape that invites the bug, but the blast radius was one handler.

**Second correction recorded.** The claim that the pre-existing wrong-Pod test had
been "passing for the wrong reason" **does not hold**. Under the round-1 design
that test passed *because* the `entry.podId !== req.podId` guard fired; the guard
was load-bearing and the test was its coverage. It became unreachable only after
per-session scoping replaced it. The test's real limitation was narrower — it
never raised two prompts sharing an id, which is why the collision escaped it.

## Judgment on the three flagged design decisions

1. **Interrupted prompt fails closed** as a `deny` with an honest reason, truth
   carried out-of-band on `push:permissionResolved` `outcome:'aborted'` — correct.
   The frozen `PermissionAnswer` union has no abort member; leaving it pending
   hangs the tool, and adding a member is a contract change.
2. **`PermissionRequestedPush.laneId` always the Matriarch** — correct given the
   freeze, and **escalated as E5**. `PermissionPrompt` carries no
   `agentID`/`toolUseId`, so attribution is discarded one layer down in
   `#makeCanUseTool`, which does hold both. Design-spec 5.4's "inline card in the
   lane that asked" is unimplementable for any Calf. The fix is one optional field.
3. **`hasMore` via a lane-filtered 1-row probe** — correct. Comparing against the
   Pod-wide `latestSeq` would report a permanent false positive for any complete
   lane-filtered read that is not the last lane written.

## Out-of-criteria work (E4), judged advisory

`#backfillAgentIds` runs at the end of every `#persist`, including the empty-batch
case that `onTurnEnd` triggers, so an id arriving after the last ingest still gets
a trigger. A lane materialized in the final batch is covered because
`#ensureLaneRow` precedes the backfill in the same call. Ordering is safe: append
and push precede the backfill, so a `setLaneAgentId` failure cannot lose events.
**Narrow gap:** ids banked for lanes not yet materialized live only in router
memory, so beach-then-reconnect discards them — `router.restore()` repopulates
`byAgentId` only from persisted lanes. Self-healing on the next dispatch;
documented in code.

## Advisory findings

- **New this round — a prompt raised during a failing `start()` is unreachable.**
  `pod-manager.ts:336-347`: the `#start` catch deletes the session without
  calling `#abortPendingFor(session)`, and `#dispose` now early-returns when the
  session is absent, so such an entry can be reached by nothing — only the
  prompt's own signal abort settles it. A **side effect of the B2 fix**, not
  pre-existing. The reviewer could not demonstrate the window (the SDK aborts the
  signal on teardown), hence advisory. One line — `this.#abortPendingFor(session)`
  beside the existing `session.disposed = true` — makes it structural rather than
  dependent on SDK teardown, matching what `onBeached` already does.
- Harness logger now captures rather than swallows; asserted empty across four
  fixtures. This is what makes the B1 regression detectable at all.
- Bootstrap `.catch` appended to the whole `whenReady().then(...)` chain, covering
  `openEventStore`, `migrate`, `registerIpcHandlers` (including its deliberate
  unhandled-channel throw), and a throw from the `onRejected` arm itself.
- `pendingPermissionIds(podId?)` overload is sound: bare ids are only unique per
  Pod now, and the doc comment says so.
