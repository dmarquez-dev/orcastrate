## Two findings that outlive this task

### 1. The frozen contract has a defect that made criterion 1 unsatisfiable as written

`contracts/transcript-filter.ts` §1 annotates each set `readonly EventType[]`. **That
annotation widens `(typeof X)[number]` to `EventType`, `Exclude` collapses to `never`, and the
exhaustiveness guard becomes vacuous.** Proved, not argued:

- **Probe A** — the contract's spelling verbatim, with a thirteenth uncovered union member.
  `tsc --noEmit --strict` exits **0. No error at all.**
- **Probe B** — T3's shipped spelling, identical thirteenth member:
  `error TS2344: Type '"thirteenth_event_type"' does not satisfy the constraint 'never'`.

So the contract's §1 annotation and its own PLUMBING docblock — "A thirteenth `EventType` must
break `typecheck:web` here" — **contradict each other**. T3 resolved it the narrowest way
available: literals bound to a module-private const with `as const satisfies readonly
EventType[]`, exported names carrying the contract's declared type verbatim, so every consumer
sees exactly the contracted type. **Not a violation — a contract defect, recorded here against
`contracts/transcript-filter.ts` §1.**

### 2. The inert-guard backlog item is confirmed independently, for the second time

Probe B also declared `const _probeArrayForm: _Unpartitioned[] = [];` on the *same* non-`never`
type that made the `_AssertNever` line error. **That line produced no error**; the file's only
diagnostic was the `_AssertNever` one. The empty array literal satisfies any array type.
`src/main/store/schema.ts:209-210` is exactly that spelling, so `_UncoveredAtSchemaHead` never
fires. This is now confirmed by two independent agents in this session.

**Correction to the backlog's own citation:** the inert form is at `schema.ts:209-210`, not
`210-212`. And `schema.ts:221` notes a second guard there is "SPELLED DIFFERENTLY … ON
PURPOSE", so the guards in that file are **not uniformly inert** — the backlog item should say
which one it means.

## Fail-first, corroborated independently

The reviewer reasoned out which assertions the gate could break: gating with `return true || …`
inside `isHiddenInConversation` leaves `isStartupReconciliationNotice` itself truthful, so
**exactly six** assertions can fail — four pane tests and two unit tests. The everything-mode
pane test and the subsequence test survive **by construction**. T3's reported 6 failed / 77
passed and its `transcript-event:2` not-found message match that accounting exactly.

## Judgment call 1 — the duplicated marker string

**The tsconfig justification is confirmed.** `tsconfig.web.json`'s `include` is exactly
`["src/renderer/src/**/*", "src/shared/**/*"]`, so importing the producer would pull
main-process code into the renderer program. The cited precedent is real
(`startup-reconciliation.test.tsx:37` hard-codes the same literal). **Not importing is justified.**

**But T3's "a test pins the copy" claim DOES NOT HOLD.** The pin at
`transcript-filter.test.ts:158-170` compares the renderer copy to a hard-coded literal and to
`makeReconciliationEvent`, whose payload is **also** hard-coded (`test-fixtures.ts:147,149`).
**Nothing in the chain reads the producer.** If `startup-reconciliation.ts:28` became
`'startup_reconciliation_v2'`, all 83 tests still pass and the notice silently returns to being
hidden — precisely the regression the exemption exists to prevent. **The test pins the copy to
itself.**

Advisory rather than blocking: no acceptance criterion requires drift-resistance, and the
exemption is correct as of today's producer. But this is the same defect class as the three
inert guards this session inherited — a check that cannot fail.

## Judgment call 2 — accepting EITHER carrier

**Accept.** `pod-manager.ts:293` and `:342` stamp both carriers independently, so a one-sided
producer edit is a live failure mode. Under AND it **silently hides** the notice — unrecoverable
for the user, invisible to tests. Under OR it at worst shows one extra row. The over-showing risk
is also **bounded**, not open-ended: `:204-217` pins that the near-miss carriers do not trip it,
so "either" is not a wildcard. The residual cost — a CLI-authored `system` event coincidentally
using subtype `startup_reconciliation` — is over-showing, which the amendment's reasoning already
accepts.
