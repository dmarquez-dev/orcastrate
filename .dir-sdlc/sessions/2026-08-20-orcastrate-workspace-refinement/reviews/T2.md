## The "watched it fail" claim — checkable, and it checks out

Unlike T1's, this one could be verified, and the reviewer did.
`git show dfe5930:src/renderer/src/lanes/LaneRow.tsx` renders the pin **unconditionally**,
outside any guard, with `aria-pressed={row.pinned}`. So the shipped assertion genuinely
returns that node against `dfe5930`, and the quoted failure is exactly what that code
produces. **Note it is a runtime red, not a type red** — at `dfe5930` the fixtures still
carried `selected`/`pinned`, but vitest strips types without checking them, so the test
reaches the assertion and fails for the stated reason. Claim accepted.

## Assumption verdicts

1. **`partitionFinishedLanes` / `FINISHED_LANE_STATUSES` in `lanes/finished-lanes.ts` —
   ACCEPTED, factual claim verified.** `src/renderer/src/contracts/` contains exactly
   `renderer-panels.ts`, `renderer-state.ts`, `renderer-theme.ts`, `renderer-view.ts` — no
   `renderer-panes.ts`; that contract is a Gate-2 spec file under `.dir-sdlc/`, never landed
   as a module. A repo-wide grep for the three symbols outside `lanes/**` returns **nothing**,
   so T1 did not owe them elsewhere and nobody imports a missing symbol. The generic
   `<T extends LaneRowLike>` instantiates to §6's declared signature at `T = LaneRowLike`.
   **T5 must import from `../lanes`** — §6 reads as if the symbols live in `contracts/`, and
   they do not. Relay that to T5 explicitly.
2. **The `<ul>` itself carries `lane-rail-finished-group` — ACCEPTED, both halves.** §6
   requires finished rows to return *interleaved*, which makes a contiguous run of DOM
   impossible, so no separate wrapper could hold exactly the finished rows; both stated
   properties hold literally. The memo claim is also correct: both toggle states render a
   `<ul>` at the same position, children are keyed by `row.lane.id`, and surviving rows get
   identical `row` objects and identical callback references, so React reconciles in place and
   `memo` bails out. No remount.
3. **`aria-current` covering primary *or* follower — ACCEPTED, with a reservation.** Sound:
   both transcripts are on screen, and marking only the primary leaves the follower
   unannounced. The reservation is that ARIA treats `aria-current` as marking *the* current
   item in a set, so two rows carrying it blurs which one a rail click would replace — a
   distinction the view model draws with `focusedFollower` but exposes only as a `data-`
   attribute. See A4.

## Advisory

- **A1 — `lane-rail-finished-group` on the shared `<ul>` is a trap for T5.** When expanded,
  the element carrying that id holds *every* row, not only the finished ones, so an assertion
  like `within(getByTestId('lane-rail-finished-group')).getAllByTestId(/^lane-row:/)` reads as
  "the collapsed rows" and returns all of them. `LaneRail.tsx:89-98`. Design is right; the
  naming misleads. **Relayed to T5.**
- **A2 — the disclosure's `aria-controls` points at a list that stays visible while
  collapsed.** `LaneRail.tsx:123` targets `lane-rail-lanes`, which also holds the active rows,
  while `aria-expanded` is `false`. A screen-reader user is told a visible list is collapsed.
  Inherent to the interleaved design, so not a defect against any criterion; strict disclosure
  semantics would mean dropping `aria-controls` and relying on the counted name.
- **A3 — button names asserted via `textContent`, not accessible name.** `LaneRail.test.tsx:186-197`,
  `:315`. Equivalent today (glyph is `aria-hidden`, name from the sr-only span), but a future
  non-hidden glyph with text slips past. `getByRole('button', { name: … })` would pin the
  property criterion 2 actually names.
- **A4 — `focusedFollower` reaches assistive tech through no channel at all.**
  `LaneRow.tsx:97` exposes it only as `data-focused-follower`, and `aria-current` is now true
  for primary and follower alike. Which pane a rail click overwrites is visible but not
  announced. Consider `aria-current="page"` for the primary plus an sr-only "in the second
  pane" on the follower row.
- **A5 — two rule tests borrow their control from a sibling `it`.**
  `finished-lanes.test.ts:60-63`, `:72-74` assert only the negative; the collapsing control
  lives at `:44-47`. The file header's claim that each rule is "paired with a control row that
  does collapse" is true at file scope, not at test scope.
