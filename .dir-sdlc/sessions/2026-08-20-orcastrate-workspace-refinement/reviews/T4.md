## Assumption verdicts

1. **Icons as glyphs — decision stands, but the stated evidence is FALSE.** See advisory 1.
2. **`data-verb` — fine.** Sits beside `data-icon`, `data-status`, `data-pod-tab-index`, already
   how the suite reads shape without reading CSS. No contract names DOM attributes.
3. **One element, not two branches — reasoning right, focus correct.** React reconciles two
   sibling ternary branches of the same element type at the same position into one host node, so
   this is real semantics, not a quirk — **which means the two-branch form would also have
   preserved focus**, making the explicit single element a clarity win rather than a bug fix.
   Three tests pin it: focus stays on the run/stop control across open, the rescue fires when the
   *delete* control unmounts, and focus is left alone when it had already moved. The rescue's
   `activeElement !== document.body` guard is the correct post-unmount condition.
4. **`podDeleted` as an internal prop — established pattern, not a violation.** Naming note in
   advisory 2.
5. **`readOnly` not `disabled` — correct**, and asserting `disabled` would be asserting a
   behaviour the composer rejects.

## Advisory

1. **A comment that is wrong, in the task whose criterion 9 exists because wrong comments are
   worse than none.** `PodTab.tsx:12-13` asserts the codebase "has no SVG anywhere, so a glyph is
   the convention rather than a shortcut." **`grep -rln "<svg" src/renderer/src` returns
   `src/renderer/src/lanes/LaneRow.tsx`** — `PinGlyph()` at lines 39-55 is an inline `<svg>` with
   a `viewBox` and a `path`, landed by T2 in this same session. The *choice* is still fine and no
   criterion cares. Narrow the wording to "draws its small chrome icons as characters" and drop
   "no SVG anywhere".
2. **`DeletePodDialogProps` deviates from the `*InternalProps` pattern it cites.** It declares an
   interface named identically to the frozen one but with an extra `podDeleted` member, whereas
   `PodBarInternalProps extends PodBarProps` and `NewPodDialogInternalProps` — the precedent T4
   named — keep the frozen name intact and extend under a distinct name. Not a violation and not
   covered by a criterion, but **T5 consumes this surface**;
   `DeletePodDialogInternalProps extends DeletePodDialogProps` would make the frozen-versus-added
   split readable without the docblock.
3. `data-verb` emits `'stop'`, which is **not** a member of `RunControlVm['verb']`. Harmless for a
   DOM attribute; worth a one-line comment saying the DOM value is a superset of the contract union.
4. `DeletePodDialog.module.css` uses bare `1px solid` where `Beachcomber.module.css` uses
   `var(--oc-border-hairline)`. Consistent with its own sibling `NewPodDialog.module.css`; noted
   only in case a hygiene rule in T5's directory prefers the token.
5. **Deferred to the backlog, not actionable this session:** T4 asked whether
   `beachcomber/use-dialog-focus.ts` should move to `shell/` so all three dialogs share
   focus-on-open, focus-trapping and conditional focus-return. It correctly neither imported across
   the feature boundary nor duplicated the hook, matching `NewPodDialog`'s existing level instead.
   **No task in this manifest owns `shell/**` or `beachcomber/**`**, so it cannot be done here.
6. **`failure-paths.e2e.test.tsx`'s "shows the pods.open failure in the dialog when the row was
   created but would not start" tests a code path Part B deleted.** It should be **removed** by
   whoever owns `__tests__/**`, not repaired. Relayed to T5.
