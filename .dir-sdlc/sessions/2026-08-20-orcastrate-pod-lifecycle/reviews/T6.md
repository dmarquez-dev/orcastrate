## The end-to-end claim, verified rather than accepted

Confirmed. `makeWorld()` builds a real migrated `EventStore` and a real `PodManager` with real
`reconcileStartup`/`openPod`/`closePod` behind `IpcResult` envelopes and a channel-name-keyed push
fan-out; the only double is `makeInertRunner`. **No fixture writes `status: 'closed'`** —
`seedPreviousProcess` skips `updatePod` for `'closed'`, and `sqlite-event-store.ts:175` inserts Pods
born `'closed'`. Every `'closed'` the renderer sees is computed by the manager. M2 proves the
`'idle'`/live-session direction is not a constant either.

This is what closes the finding T5's review raised: `pods.close` here goes through the real
`PodManager.closePod` and the assertion reads the persisted row back out, so it cannot pass against
a stub that always says yes.

## Advisory findings

1. **`relaunch.e2e.test.tsx:66-67` imports `src/main/pod-manager` and `src/main/store` from
   `src/renderer/src/__tests__/`, which no sibling does.** No criterion forbids it, criterion 1
   requires the real `reconcileStartup()` before mount, `hygiene.test.ts:387` allows it (relative
   specifiers are exempted), and `typecheck:web --listFiles` confirms the file really compiles under
   the web project. But the stated rule in `transcript/startup-reconciliation.test.tsx`'s header —
   that the renderer may not import main — is now inconsistent with a file in the same tree. That
   header belongs to T5. **Worth a follow-up, not a change here.**
2. **`relaunch.e2e.test.tsx:196` keeps a module-level `worlds: RelaunchWorld[]`.** Drained in
   `afterEach`, and vitest runs a file's tests serially, so isolation holds — but it is the one piece
   of state not created per test.
3. **Criterion 4's `POD_STATUSES` half is pinned indirectly**, via migration 3's rendered DDL string,
   rather than by a direct identity assertion on the exported array. Equivalent in practice today; a
   direct `expect(POD_STATUSES).toEqual([...])` would be more legible to the next session.
4. **`failure-paths.e2e.test.tsx` runs 68 tests in ~47s, dominating the ~50s suite wall time.** Not
   this task's doing and not a criterion, but it is the whole-repo bottleneck.
