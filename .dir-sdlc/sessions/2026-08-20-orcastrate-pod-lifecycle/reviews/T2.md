## Advisory findings

1. **`#appendReconciliationEvents` (`pod-manager.ts:333`) has an untested fallback branch.** It falls
   back to `data.orphanedLaneIds[0]` when `getMatriarchLane` returns null, then silently `return`s if
   that is also undefined. The fallback is unreachable given the caller's guard (a lane changed ⇒ at
   least one id exists), so it is untested defence. Not a criteria violation — noted because an
   untested branch in the durable-record path is the one place a future refactor could lose a notice
   without a test noticing.
2. **`helpers.ts`'s `hasSession` probes `#sessions` through `interrupt()`.** Faithful today, but it
   couples the openness invariant to `#requireSession`'s error code; if `interrupt` ever gains a
   pre-session guard, the invariant test would silently weaken.
3. **`seedCounter` in `helpers.ts` is module-global and never reset**, so seeded Pod ids are unique
   per worker but not deterministic across a `--sequence.shuffle` run. No test asserts on the id text,
   so nothing is at risk now.
