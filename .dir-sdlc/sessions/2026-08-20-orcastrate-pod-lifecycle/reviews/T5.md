## Advisory findings

1. **`pod-lifecycle.test.tsx:105-148` is near-tautological at the renderer boundary.** It reads as
   proving `pods.close` resolves `{ ok: true }` and leaves the Pod reading `'closed'`, but the stub's
   close always returns ok and the fixture's status never changes, so both halves are close to
   assertions about the stub. The substantive proof is the main-side code path
   (`pod-manager.ts:447`), which no test in this diff exercises. **Carried forward to T6 at dispatch**
   — its relaunch suite is the natural home for the end-to-end version.
2. **The new hygiene regexes assume single-word lowercase status names.** `STATUS_VARIABLE` and
   `unionMembers` would mis-parse a future hyphenated status — but loudly, via the exhaustive
   key-list assertion, so it fails safe rather than silently.
3. **The base `.statusDot` rule keeps a raw `border: 1px solid`** (pre-existing, not introduced
   here). If the hygiene length rule ever tightens, that line is the one it will catch.
