## The three judgement calls the review was asked to examine

- **Writing the two missing tests was the right call.** Criterion 4 says "A test asserts…" and
  criterion 5's preload clause states a property to hold — neither is worded as "confirm the existing
  test still passes", the way the `src/main/ipc` fence clause is ("asserted by the existing source
  scan", which did exist and is green unmodified). Reporting those two unmet would have been a
  literalist reading that left the required property unpinned. What was written does establish the
  properties: the argument guard is type-level and exhaustive over the namespace, and the preload
  scan checks both directions — constant referenced, literal absent.
- **Non-vacuity confirmed independently.** The reviewer compiled the same machinery against four
  deliberately violating shapes. The real contract compiles clean; each violation errors:
  `list()` returning `(Pod & {opened})[]` → `Type 'boolean' is not assignable to type '{ POD_METHOD_RETURNS_A_PARALLEL_OPENNESS_FIELD: "list"; }'`;
  `open()` returning a scalar `Pod & {isOpen}` → the same error keyed `"open"`, proving `Element<T>`
  does not silently pass non-array returns; `update(req: {podId, status})` →
  `POD_METHOD_ACCEPTS_A_STATUS_OR_OPENED_ARGUMENT: "update"`; and
  `Exact<Pod & {opened}, Pod>` → `Type 'true' is not assignable to type 'false'`, proving the
  bidirectional check rejects a widened supertype. The runtime sweep's vacuity guard is also real: it
  requires `sawAPod` (a reply carrying both `status` and `lastActiveAt`), and the suite passes.
- **The docblock binds rather than describes.** Prohibitive voice throughout ("NO METHOD HERE MAY
  EVER CARRY", "This is a PROHIBITION, not a preference", "is forbidden here for that reason"), names
  the rejected `PodView` proposal and the gate that rejected it, and gives the reason each rule
  exists. A later patch author would read it as a constraint with a rationale to argue against, not a
  snapshot to update.

## Advisory findings

1. **The `src/main/ipc` no-validator source scan is a name-based regex denylist** over `opened`,
   `PodStatus`, and `requireStatus|isAllowedStatus|POD_STATUSES`. A validator spelled differently —
   `assertPodStatus`, or an inline `['idle','running',…].includes(x)` — would pass it. The criterion's
   actual requirement is carried by the type-level and runtime halves, which are sound; this third
   scan is belt-and-braces and should not be mistaken for the load-bearing one.
2. **The preload literal scan's per-channel assertion tests only single-quoted spellings.** A channel
   name written as a template literal would evade it; the catch-all covers double quotes but not
   backticks. Low risk given the file's style, but the gap is real.
3. **`Element<T>` unwraps only a top-level array**, so a hypothetical nested reply
   (`{ pods: PodView[] }`) would evade the type guard. The recursive `allKeys` runtime sweep would
   still catch it, so the pair is not blind — worth knowing if the type guard is ever reused alone.
4. The docblock asserts `PodStatusPush` carries `exitCode` and `detail` "for `'beached'` alone", but
   only `exitCode` carries that comment in the type itself. Factually correct today
   (`pod-manager.ts:1092` is the sole writer of `detail`, and `events.ts:82` documents both as the
   beached cause), so an observation rather than a defect.
