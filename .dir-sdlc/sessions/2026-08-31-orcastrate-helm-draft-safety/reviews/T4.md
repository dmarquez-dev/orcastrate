## Advisory findings

- **A1 — the comparison surface is absent before a scope is chosen.** `HelmPanel.tsx:113`. With
  `draft === null` no surface renders, so criterion 6's empty state is not on screen in that one
  situation. Judged met rather than not-met: the criterion's subject is the surface's states, the
  state in question is unreachable-with-content per the store trace, and `COPY.scopeUnchosen`
  already occupies that moment. The letter admits the other reading, so it is recorded.
- **A2 — `compareRequested` never resets, so a later unrelated `actionError` can be
  misattributed.** `HelmPanel.tsx:53,62-63`. After a failed compare, `incoming` stays null; a
  subsequent failed save then satisfies `compareRequested && !comparing && incoming === null`
  and prints e.g. an `EROFS` inside the comparison surface instead of the error banner. Narrow —
  it needs a failed compare followed by a different failure — and it is the mirror of the bug the
  flag prevents. Clearing the flag when `actionError` transitions would close it.
- **A3 — the empty-state copy points at an affordance that may not be on screen.**
  `COPY.comparisonEmpty` says "Compare with the file on disk to fetch its current contents", but
  the button exists only on the conflict banner (`HelmNotices.tsx:104`). With a draft and no
  conflict, the surface names an action the user cannot reach.
- **A4 — the `resolve(` rule is over-broad; the reviewer agrees with T4's read.** `rules.ts:92`
  builds `'resolv' + 'e('` and `:145` matches by `text.includes`, so `Promise.resolve(`,
  `deferred.resolve(` and any other `resolve(` trip a rule aimed at `path.resolve`. T4 worked
  around it rather than narrowing it — defensible, since the rule has never fired wrongly in
  shipped code, but the workaround is now a comment future authors must rediscover.
- **A5 — the confirmation scrim is opaque, and the reason is real.** `Helm.module.css`
  `.confirmScrim` uses `background: var(--oc-bg-app)`. `renderer-theme.ts`'s `TOKENS` has
  `bgApp`, `bgPanel`, `bgRaised`, `bgHover`, `bgSelected` and **no** overlay, opacity, alpha or
  scrim token, so the panel behind is hidden rather than dimmed. A proper fix needs a token from
  the frozen theme contract.

## Reviewer's note on the new source rule's reach

The rule at `rules.ts:150-172` forbids `compare()` and a React effect hook sharing a *file*. It is
deliberately conservative and does **not** catch a `compare()` called directly from a render body
with no effect hook present. Criterion 7 is satisfied on the grep plus the falsifiable
`not.toHaveBeenCalled()` test, so this is a note on the rule's reach, not a gap in the criterion.
