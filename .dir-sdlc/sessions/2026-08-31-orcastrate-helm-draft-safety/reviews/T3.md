## Advisory findings

1. **Criterion 2's literal form was genuinely unsatisfiable — deviation accepted.** For the
   string `setOpenPanel(null)` to appear anywhere, `requestClose` would need a resolution path
   distinct from `requestOpen`'s, which the frozen contract forbids in terms: "Both are
   implemented over ONE private guarded transition." Inside the guard module the setter arrives
   as a parameter named `apply`, so the identifier cannot appear there at all. The intent — one
   owner of the state move, inside the controller — is met and grep-verified.
2. **The `PanelBar` toggle removal is contract-compelled, and it does cost a close route.**
   Criterion 16 is genuinely unsatisfiable with the toggle intact: a toggle routes the re-click
   to `onClose()` → `requestClose()` → `transition(null)`, which asks the guard. The only
   alternatives are bypassing the controller (violating criterion 2 and `ShellCloseRouting`) or
   closing without asking — the exact draft loss this session exists to prevent. The frozen
   contract states it gesturally too: "re-clicking the open panel's own button must not raise a
   dialog", and `ShellCloseRouting` already calls the per-panel buttons "panel-switch buttons".
   **Cost: three close routes become two.** The strip close button and Escape both survive and
   are both test-covered, so nothing is trapped — but a user whose habit was the toggle loses it
   silently, and no criterion asked for that. **For Gate 3, as a deliberate UX change.**
3. **`aria-pressed` now announces a toggle that cannot be un-pressed from the button itself.**
   `PanelBar.tsx:78` still emits `aria-pressed={open === key}` and `PanelBar.test.tsx:50-59`
   asserts both values. The attribute still truthfully reports open state, and changing it would
   edit a pre-existing test criterion 11 protects. Follow-up decision: keep `aria-pressed` as a
   state indicator, or move to `aria-current`.
4. **Criterion 10's focus assertion is the weaker half of that test.** `:447` re-checks the same
   region node captured at `:435`; on the declined path nothing attempts to move focus, so it
   passes largely by nothing happening. Still falsifiable — an implementation that blurred the
   region or let `PanelBar`'s focus-return effect fire would redden it — so criterion 10 stands.
   But the panel-stays-open half is what defect C actually demonstrated; the focus half rests
   on absence.
