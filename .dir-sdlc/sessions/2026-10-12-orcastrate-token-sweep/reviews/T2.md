## The defect this task caught in itself

The implementer's first pass used an Edit whose `old_string` was `"  border: 1px "`; **the
trailing space was stripped**, producing `border: var(--oc-border-hairline)solid …` on all
14 lines. That is invalid CSS — the browser discards the whole declaration, so all 14
borders would have vanished on screen.

**Criterion 2's census grep passed the defect cleanly.** Only criterion 3's zero-pixel diff
exposed it. The reviewer verified the blind spot two-sidedly on one scratch file: against
`border: var(--oc-border-hairline)solid var(--oc-border-strong);` the census regex returns
exit 1 (blind) while a concatenation probe returns exit 0 (hit). This is the finding that
produced escalation E2 and amendment A1.

## Advisory findings

1. **The session's repo-wide census will not guard against a concatenation regression.**
   The census predicate is blind to `var(--oc-border-hairline)solid`, a declaration the
   browser discards entirely — demonstrated two-sidedly on one file. **Escalated as E2 and
   resolved by the user: amendment A1 adds a terminator criterion to T5.**
2. **Both new docblocks state counts and exhaustive enumerations that no scanner
   enforces** — PodBar's "two declarations still carry a bare `px`" and DeletePodDialog's
   "the only raw values left are …". Both true today; both will go stale silently on the
   next edit, since the census checks border widths and tracking, not these enumerations.
   Not blocking: criteria 5 and 6 ask only that the claims be true as the task leaves the
   files.
3. **`PodBar.module.css:198` carries an unguarded `38px` in inline prose** ("the visible
   chip is short because a tab is 38px tall"). An inline comment, not the header docblock,
   so criterion 5 does not reach it, and not a declaration, so it does not falsify the
   "two declarations" count. Nothing ties that figure to the tab's actual height.
4. **`--oc-border-thick` appears twice in `PodBar.module.css` but only one use is a border
   width** — line 155 is `border-width`, line 175 is `height: var(--oc-border-thick)` (the
   `closed` status bar). The docblock's claim is unaffected and true. Noted because
   criterion 5's own phrasing ("already uses `--oc-border-thick` at lines 152 and 172")
   could read as though both were border widths — an imprecision in the criterion the
   orchestrator wrote, not in the implementation.
