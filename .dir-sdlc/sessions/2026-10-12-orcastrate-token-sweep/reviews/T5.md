### Blocking finding B1 — criterion 13

**A universal T5 added to the prose is false: six bare border widths remain unconverted.**

`src/renderer/src/__tests__/hygiene.test.ts:555-557` — "2026-10-12-orcastrate-token-sweep
converted every remaining bare border width and letter-spacing in the renderer." Six
untokenised keyword border widths remain in the tree as T5 leaves it:

- `src/renderer/src/composer/Composer.module.css:15, 44, 70`
- `src/renderer/src/permissions/PermissionCards.module.css:27, 85, 100`

each `border…: thin solid var(--oc-…)`. Confirmed by the reviewer with a positive-controlled
grep over the 9 census properties for `thin|medium|thick` (13 hits, 7 of them
`var(--oc-border-thick)` token references; the 6 `thin` sites are the real ones), and
independently by the orchestrator before the review was dispatched.

`thin` is a CSS border-width keyword, so **criterion 2's frozen raw-length predicate
correctly does not flag it, and the implementer was right to raise it as an advisory rather
than widen a frozen criterion.** The defect is the prose: this file's own vocabulary uses
"bare X" for a non-token literal — the very paragraph being replaced said "reached for bare
`1px`, `0.04em` and `font-weight: 700`" — so "every remaining bare border width" reads as
"no untokenised border width remains", and six do. The letter-spacing half is true.

**This is the exact shape of the previous session's only blocking finding, and the
implementer knew the six sites when it wrote the universal.**

Ranked remediation options, as the reviewer worded them:

1. **Scope the clause to what was actually converted and name the survivors in the same
   sentence.** Best fit: makes the sentence true, keeps the paragraph's purpose of recording
   that the deferred decision was taken, and leaves the next reader a pointer instead of a
   surprise — the whole function of this docblock. Evidence `repo`: the file's own
   convention of recording what a rule does *not* hold, e.g. `lanes/LaneRail.module.css:10-13`'s
   "Raw lengths DO remain… The survivors are…".
2. **Narrow the clause to the raw-length predicate only**, dropping "bare". The minimal edit
   that makes the claim true, matching the header bullet's already-correct scoping — but it
   leaves the six `thin` sites recorded nowhere in the file. Evidence `repo`: the header
   bullet at :23-24.
3. **Add the keyword forms to the census predicate** so the universal becomes true by being
   enforced. **Ranked last and recommended against:** `RAW_LENGTH`,
   `BORDER_WIDTH_PROPERTIES` and the sample sets are frozen contract surface, the contract
   states the populations it is frozen against, and converting six shipped borders' pixels
   requires an escalation, not a review round. Evidence `repo`:
   `contracts/token-sweep-census.ts`.

**Orchestrator's dispatch:** option 1 directed unless the implementer has a specific reason
to prefer 2; option 3 explicitly forbidden for this round.

### New advisory finding (round 2)

**The deferral's pixel rationale is probably factually wrong — which argues the conversion
is safer, not riskier.** The new paragraph says widening the predicate to the keyword forms
"would change six shipped borders' pixels, which is a design decision and not a test
change". The reviewer believes `thin` computes to `1px` in Chromium — the only engine this
app renders in — making the conversion visually neutral. It labelled this **`judgment`** and
deliberately spent no lookup, correctly, since no criterion turned on it.

**Orchestrator spent one lookup to settle it, because it determines how the backlog item is
framed and the user decides at Gate 3.** Result: MDN states `thin` ≡ `1px`, `medium` ≡ `3px`,
`thick` ≡ `5px`, but the CSS specification fixes only the *ordering* and leaves the widths
UA-defined, and no Chromium source confirms its exact values; the authoritative check is
reading `getComputedStyle(el).borderTopWidth` in Chrome. So the belief is well-supported but
not spec-guaranteed. **Correct framing for the backlog: the conversion is probably
zero-pixel, and this project owns the instrument to confirm it empirically** — the
Playwright-driven Electron hand-run. Not an edit this round needs: criterion 13 binds counts
and universals about the tree as the task leaves it, and this is a forward-looking prediction
about a change deliberately not made.

Round-1 advisories 3 and 4 were not re-raised and remain advisory. The reviewer noted for
the record that excluding them to protect the criterion-14 measurement was the right call,
since both would have moved a test name or a block count after the number was taken.
