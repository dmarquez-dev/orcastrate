## Advisory findings

1. **The implementer's stated argument for criterion 1 is factually wrong, though its
   conclusion is sound.** It argued no rule-body line moved because "every hunk's old line
   number equals its new one". The actual diff shows the docblock hunk `@@ -5,2 +5,10 @@`
   and a uniform **+8** shift on every later hunk (old 17 → new 25, old 25 → new 33, …
   old 401 → new 409). The conclusion holds for a different reason: each border hunk is one
   deleted line against one added line, which is what rules out a shorthand split.
   Recorded so a later reader does not inherit the false invariant.
2. **Criterion 9's evidence was gathered at a narrower scope than the criterion names.**
   The implementer ran `git status --porcelain src/renderer/src/lanes` (2 lines); the
   criterion asks for `src/renderer/src`. The narrow scope cannot in principle distinguish
   a T1 edit outside `lanes/` from a peer's. The reviewer ran the criterion's own scope and
   found it clean, so the verdict stands — but the reported command does not establish what
   the criterion asks.
3. **The docblock's "survivors" sentence is exact for raw *lengths* and slightly
   under-inclusive if read as all raw geometry.** Unlisted raw literals remain:
   `border-radius: 50%` (219, 374), `width`/`height: 100%` (22, 153), `clip-path: inset(50%)`
   (431) and `animation: … 1.4s …` (265, 306). Under the sentence's own framing these are
   percentages, a time and a flex fraction rather than lengths, and criterion 7 frames the
   concern as raw lengths — so this is not a false claim. Saying "raw *length* survivors"
   would close the ambiguity; the existing `1fr` entry is already broader than "lengths",
   which is what creates it.

## Orchestrator note

Advisories 1 and 2 are both about the *quality of the evidence offered*, not about the code,
and in both cases the reviewer re-derived the correct result itself. They are recorded
because this project's standing rule is that a count or an invariant nobody verified is a
claim — and advisory 1 is an instance of exactly that, caught by the review rather than by
the implementer's own check.
