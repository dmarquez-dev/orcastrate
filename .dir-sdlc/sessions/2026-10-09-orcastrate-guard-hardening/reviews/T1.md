### Reviewer's ruling on the two risks the orchestrator flagged

**The recovered-copy concern does not weaken criterion 4.** Two reasons, in the
reviewer's words. First, the vacuity is **structural, not empirical**: with
ingestion dead, `baseline` is `[]` and `withSend` is `[typed]` (the typed row
comes from `h.manager.send` at `:385`, before `driveFixture`), so the old
`toHaveLength(0 + 1)` and `toEqual([typed])` both reduce to `[typed]` and
*cannot* go red under that injection regardless of tree state. Second,
`tests/unit/ipc/helpers.ts` and every file under `tests/fixtures/protocol/` are
byte-identical to `a186f06` — `git diff a186f06 --stat` over both paths returns
empty — so the suite's whole fixture-and-driver surface in the recovered-copy run
genuinely was the base version.

**The injection-site substitution is correct, not a weakening.** Criterion 4
offered `driveFixture` as an example; what it requires is that the replay ingest
nothing. Injecting at the `driveFixture` call site inside the task's own `replay`
helper (`:386`) achieves exactly that while staying inside the ownership set —
`tests/unit/ipc/helpers.ts` is shared with concurrent peers, so editing it would
itself have been a contract violation. The call-site injection is also *narrower*:
it isolates the criterion-7 loop instead of perturbing every test that drives a
fixture.

**Contract compliance:** one file, inside the ownership set; no fixture, helper,
or peer file touched; no contracts edited; nothing written outside the assigned
scratch directory.

   what it claims.
