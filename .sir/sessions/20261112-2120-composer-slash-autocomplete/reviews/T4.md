## Advisory

1. **A1. The suggestion list probably paints above the New Pod and Delete Pod modal scrims.**
   - **Cause.** `Composer.module.css:129` gives `.suggestions` `z-index: 1`. The `position: fixed` dialogs use the same value (`NewPodDialog.module.css:3`, `DeletePodDialog.module.css:11`).
   - **Why the list wins.** The dialogs render earlier in the DOM (`PodsChrome.tsx:369,379`, inside the pod bar at `WorkspaceLayout.tsx:45`) than the composer region (`:63`). No ancestor creates a stacking context, so the later DOM node paints on top.
   - **How it is reached.** The list's visibility depends on the draft, not on focus, so typing `/` and then opening New Pod would leave the list showing, and pressable, over the modal.
   - **Status.** Derived from the CSS and not observed. No criterion covers stacking.
   - **Suggested fixes.** Add `isolation: isolate` to `.composer`, or drop the `z-index` from `.suggestions`.
2. **A2. The open list stays rendered and clickable after the textarea loses focus**, for example on Shift+Tab or a click elsewhere. `listOpen` depends only on text, disabled and dismissal. Part B says nothing about blur.
3. **A3. Dismissal gap.** If the parent rewrites `text` away and then back with no local edit, the list stays dismissed. Part B's "since the text last changed" would reopen it. No path in the app does this.
4. **A4. The implementer's judgment assumptions are consistent with part B.**
   - Modified keys fall through, and base Enter ignores modifiers (`Composer.tsx:208-212`).
   - There is no combobox role. ARIA 1.2 allows `aria-activedescendant` and `aria-autocomplete` on a textbox, but screen-reader announcement cannot be checked in jsdom.
   - The selection resets by row identity, which relies on T3 keeping the same array object between pushes.
5. **A5. No type errors found by reading.** The only `<Composer` site without `commands` is `App.tsx:236`, which belongs to T5 and is expected.

6. **A6. Automated security review, recorded by the orchestrator after the phase.** The security-guidance plugin flagged "remote data suppresses a safety control" (MEDIUM): while the list is open, Esc closes it and does not interrupt.
   - **Why it ships this way.** This is the signed behaviour, spec DoD 8 and C99, and part B of the contract.
   - **What actually opens the list.** Only the user's own draft does (a leading `/` with no whitespace). The pushed data controls only which rows appear. A second Esc interrupts as at base.
   - **The residual risk.** A user who types `/…` while a turn runs needs two Esc presses to interrupt.
   - **Options for Gate 3.**
     1. Accept it as designed.
     2. Make Esc both close the list and interrupt while a turn is in flight.
     3. Carry it as a backlog row.
