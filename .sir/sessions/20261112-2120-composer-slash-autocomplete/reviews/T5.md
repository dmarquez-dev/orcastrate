## Advisory

1. The implementer reported that C122 had never been seen failing, because the defect lives in T3's store, outside T5's owns. The reviewer's `store.ts:518` injection closed that gap: the test fails at exactly the C122 assertion.

2. An automated security review (the security-guidance plugin) of the committed `App.tsx` flagged the pushed command list as untrusted content inserted into the outbound draft (MEDIUM). The orchestrator's assessment:
   - **Who supplies the list.** It comes from the user's own CLI subprocess: built-in commands plus the user's own `.claude` commands and skills.
   - **What accept does.** Accepting only writes `/<name> ` into the draft, and sending needs a second, visible Enter.
   - **The gap.** `normalizeSlashCommands` (`src/main/pod-manager/slash-commands.ts`) requires a non-empty string `name`, but it does not reject whitespace, newlines or control characters. A name like that would also never match the Composer's single-token prefix rule.
   - **Proposed follow-up.** Have main drop names that are not one printable token, and strip control characters from `description`. This would be a backlog row at Gate 3, not a defect in any task's criteria.
   - **Not taken.** The plugin also suggested keying the list by podId at the call site. T3's C62–C64 and T5's C122 already cover active-Pod scoping.
