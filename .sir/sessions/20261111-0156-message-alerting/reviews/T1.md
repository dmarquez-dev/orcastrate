## Advisory findings

- A1 (contract gap). For `message === ''` React renders no Text node, so the guarantee that the message element's first child is "a single Text node whose data is `message`" (`contracts/notifications.ts:124-125`) cannot hold. `textContent` is still `''` and nothing throws. See `NotificationItem.tsx:53-55`. The implementer disclosed it, and no criterion covers it.
- A2 (accessibility). A `role="status"` item inserted already holding its text may not be announced by some screen readers. The contract fixes this DOM shape (`NotificationItem.tsx:53`).

## Human observations (for T6 / Gate 3)

- With a scrimmed dialog open, raise an error notification. The item should paint above the scrim at the bottom-right corner, and nothing else should be veiled.
- With a screen reader on, raise an info notification and then an error. The error should be announced assertively and the info politely.
- Tab onto a dismiss control, then dismiss the last item. The focus-visible outline should show on the control, and then on the viewport.
